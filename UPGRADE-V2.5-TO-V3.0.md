# Passer de la 2.5 à la 3.0

Ce qui s'écrit autrement en 3.0, avec la nouvelle écriture, puis ce que la 3.0 fait d'elle-même. Le détail de chaque changement est dans le [journal des modifications](CHANGELOG.md), section 3.0.0.

## Ce qui s'écrit autrement

| En 2.5 | En 3.0 |
|---|---|
| `happy-dom` 15 ou plus (la dépendance du rendu serveur, du prérendu et des tests d'application) | `happy-dom` 20.11.2 au moins : un projet qui déclare une version plus ancienne (`"happy-dom": "^15"`) voit `npm install` refuser la 3.0 (`ERESOLVE`) ; montez-le en même temps : `npm i -D happy-dom@^20.11.2` (ou `npm i happy-dom@^20.11.2` s'il est dans vos `dependencies`) — cf. « Rendu serveur » |
| `µminmax($volume, 0, 100)` | un bloc `<vars>` avant le `<script>` : `$volume int 0..100` — µminmax est retiré (cf. « Types ») |
| `<@select>`, `<@switch>`, `<@code>`… (composants cœur) | `<@@select>`, `<@@switch>`, `<@@code>`… ; `<@select>` ne désigne plus qu'un composant de votre projet |
| la balise `<mjs-select>` (sélecteurs CSS, tests) | `<mjs-core-select>` (`<mjs-core-nom>` pour chaque composant cœur) |
| un composant du projet nommé comme un composant cœur le remplaçait partout | chacun garde son nom : `<@select>` est le vôtre, `<@@select>` celui du cœur |
| `@transition.fade`, `@in.fly={ y: 200, duration: 2000 }`, `@out.fade` | `@transition=*fade`, `@in=*fly(up, distance: 200, duration: 2s)`, `@out=*fade` — l'ancienne écriture est une erreur de compilation qui donne la nouvelle, avec les réglages écrits (`@in.fly={ y: 22, duration: 220 }` → `@in=*fly(up, distance: 22, duration: 220ms)`) ; une seule construction les donne toutes, une ligne chacune par composant ; un réglage calculé (`{ y: $h / 2 }`) passe par une variable à poser dans le `<script>` (`$distance = $h / 2`, puis `distance: $distance`) ; pour `zoom`, `zoomOut`, `elastic_fly` et `elastic_scale`, le message donne l'effet qui les remplace, et un modificateur écrit (`.global`, `.shared`) est gardé dans la proposition |
| les animations `zoom`, `zoomOut`, `elastic_fly`, `elastic_scale` | `*scale(start: 0.55)` (ou `1.45`), et la courbe `easing: elastic-out` sur `*fly` ou `*scale` |
| `µ.devPanel()`, `µ.devObject(v)` | `µconsole`, `µconsole v` (cf. « Débogage ») |
| `<style name="default">` | refusé : `default` est réservé au modèle par défaut (`{? default}`) |
| `µanim.create 'spin'` — le nom d'un effet (`spin`, `pulse`, `glitch`, `zoom`…) | la transition n'est plus jouée : le nom désigne l'effet ; donnez-lui un autre nom (`µanim.create 'tourbillon'`) |
| `@i18nPlaceholder auto`, `"i18n": { "placeholder": "auto" }` (des barres grises à la place des textes, le défaut) | `@i18nPlaceholder *skeleton`, `"placeholder": "*skeleton"` — `auto` est une erreur de construction qui donne la nouvelle écriture ; sans rien écrire, le module attend ses textes, caché, puis paraît d'un coup (`wait`, cf. « Traductions ») |
| un back signe ses requêtes au pont MJS WS avec `x-mjs-ws-timestamp` et `x-mjs-ws-signature` | il envoie aussi `x-mjs-ws-nonce` (une chaîne neuve de 8 à 64 caractères à chaque requête), ajouté en dernier champ de la chaîne signée ; les recettes `curl` et Rails de la doc le font. Sans lui, réponse `401` qui dit quoi ajouter. Pour garder l'ancien comportement : `bridge: { nonce: false }` (ou `"ws": { "bridge": { "nonce": false } }` dans `mjs.config.json`) |
| la présence d'un salon (qui y est connecté, avec ses méta) se lisait par tout client | elle n'est servie qu'aux membres du salon : un client qui la demande sans être entré reçoit un refus (`µ:error`, code `presence-denied`), et qui quitte le salon cesse de la recevoir. Pour la montrer à tous : `app.room('partie-42', { presence: 'public' })` ; pour garder l'ancien comportement partout : `rooms: { canSeePresence: () => true }`. Pendant une mise à jour progressive, un client d'avant la 3.0 qui la demande avant d'entrer reçoit ce refus : `rooms: { canSeePresence: (room, client) => … }`, avec la règle d'entrée du salon, la lui rend |
| qui est connecté au serveur (`sock.presence()` sans salon) se lisait par tout client authentifié | la présence globale n'est montrée à personne : le client reçoit `µ:error { code: 'presence-denied' }` et sa liste reste vide ; `mjsWs({ presence: 'public' })` la montre à tous ; votre back la lit toujours par le pont (`GET /presence`) |
| un flux déclaré sans garde (`app.stream('scores')`) était servi à tous | il n'est servi à personne : écrivez `app.stream('scores', { public: true })` pour l'ouvrir à tous, ou `{ room }` / `{ canSubscribe }` pour le réserver ; pendant le développement, un avertissement nomme chaque flux fermé et la ligne à écrire |
| suivre l'écran (`*follow`, `followPackage()`) : tout membre du salon pouvait mener | personne ne mène par défaut ; `followPackage({ canLead: (client) => … })` dit qui mène (`() => true` pour l'ancien comportement) |
| un visiteur sans compte se désignait par son id de connexion (`c5…`), qu'un compte pouvait aussi porter | il se désigne par `anon:` suivi de son id de connexion : `app.sendUser('anon:' + client.id, …)`, `app.room(salon).kick('anon:' + client.id)`, `POST /send` et `POST /room/kick` avec `user: 'anon:…'` ; c'est aussi sa clé de présence et son id dans la discussion, le hall, les réactions, le suivi d'écran et les webhooks. Un compte garde son `identity.id` ; un id de connexion nu ne désigne aucune personne (pour une seule connexion, passez l'objet client à `kick`, ou `client` au pont). Un compte dont l'id commence par `anon:` est refusé à la connexion |
| dans `except` (`POST /broadcast`, `POST /room/send`), une chaîne pouvait désigner une connexion | une chaîne désigne toujours une personne (id de compte, ou `anon:…`) ; pour exclure une seule connexion, écrivez `{ "client": "<id de connexion>" }`, comme pour `POST /room/kick` ; un tableau peut mêler les deux, et la règle vaut d'un processus à l'autre |
| une clé que `accountsPackage({ … })` ne lit pas (faute de frappe) était ignorée en silence | elle arrête le démarrage, avec la clé la plus proche en suggestion et la liste des options (cf. « Serveur temps réel (MJS WS) ») |

## Ce que la 3.0 fait d'elle-même

Ce que la 3.0 fait **d'elle-même** et que la 2.5 ne faisait pas — chacun se coupe, dans `mjs.config.json` (la barre de navigation, dans le code de l'appli) :

- **une barre de navigation** en haut de la page pendant un changement de page qui tarde (liens, formulaires, routeur) : un trait de lumière, qui ne s'éteint que pour un composant attendu par la navigation du routeur. `µ.config.navProgress = false`, dans le code de l'appli, l'éteint.
- **un squelette pendant les chargements** : un `{await}` sans branche d'attente montre la forme de sa branche `{success}` (des barres à la place des textes) ; un module dont les textes traduits ne sont pas encore arrivés attend, caché, et paraît d'un coup (`wait`, le défaut ; au bout de 3 s sans textes, durée réglable, il paraît avec des barres grises, cf. « Traductions »). `"effects": { "skeleton": [] }` rend l'ancien comportement des `{await}` ; `["await", "components"]` l'étend aux composants dont le code arrive.
- **le changement de thème en cercle** : quand un clic change le thème, le nouveau s'ouvre en cercle depuis le point cliqué. `"effects": { "theme": "none" }` rend la bascule immédiate.
- **les effets économes** : sur un appareil qui peine, les effets lourds (particules, fumée…) s'allègent. `"effects": { "lite": "off" }` les garde tels quels.
- **`*guard` sur tout champ lié à une variable typée** (`<input value=!{$age}>` avec `$age int 18..120`) — seulement si vous écrivez des types. `"effects": { "guard": false }` le rend muet ; `{ "guard": { "delay": "1.5s" } }` règle la pause qui précède sa bulle (une seconde par défaut, au plus 24 h (86 400 000 ms) : au-delà, erreur de construction, par `mjs.config.json` comme par l'API `new Bundler({ … })`).
- **Modifié — les gestionnaires `@click` (et ceux de tout événement qui remonte : `@input`, `@keydown`…) jouent à la remontée, comme un écouteur posé sur la balise** : l'écouteur natif d'une balise du composant (une bibliothèque, `@attach`) joue avant eux et son `stopPropagation()` les arrête ; `@click.stop` sur un conteneur ne prive plus la balise cliquée de ses propres écouteurs ; un composant enfant joue avant le gestionnaire que son parent pose sur sa balise, et un `.stop` de l'enfant l'arrête. Un `@click.prevent` posé par le parent sur la balise d'un enfant retient toujours un lien écrit dans l'enfant (une carte cliquable qui contient un lien) : la navigation de MJS n'agit qu'une fois l'événement fini, comme un lien du navigateur ; un écouteur de la page qui appelle `preventDefault()` sur cette balise le retient aussi (posé sur `window`, il arrive trop tard). Un bouton à `@click.stop` placé DANS un lien dont le `@click.prevent` retient la navigation (une carte-lien) arrête ce gestionnaire : le lien part alors après le geste du bouton. Écrivez `@click.stop.prevent` sur le bouton. Exception : `@submit` joue avant les écouteurs posés sur le formulaire, si bien qu'un `@submit.prevent` retient toujours l'envoi, même quand un script de la page coupe l'événement. Les événements qui ne remontent pas (`focus`, `blur`, `load`, `scroll`…) gardent leur ordre ; le contenu glissé dans un `<@slot>` est routé après les écouteurs de la balise cliquée, mais le composant qui l'a écrit joue encore avant celui qui le reçoit. Il reste un seul écouteur par type d'événement et par composant (le contenu glissé en ajoute un, le temps d'un événement).
