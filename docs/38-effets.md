# 38 · Effets

> 📚 Pas de chapitre de tuto interactif dédié pour l'instant : cette page se suffit à elle-même. Les encarts 🎓 *Pour débutants* dépliables donnent l'explication pas-à-pas ; le corps de la page reste la référence dense.

Un effet donne une allure ou un mouvement à une balise, **en un mot** posé sur elle : `*neon`, `*glitch`, `*tilt`, `*cycle`, `*loader`… Ni CSS ni script à écrire. Les réglages, s'il en faut, s'écrivent entre parenthèses. 117 effets, rangés en familles.

```html
<h1 *neon>Soirée</h1>
<h1 *neon(#f0f, where: both, on: hover)>Soirée</h1>
<div class="card" *tilt(15, glare: true, depth: 40)>…</div>
<button *ripple *confetti>Valider</button>
<span *count(separator: '.')>12480</span>
<h2 *gradient([#22d3ee, #ff4fa3, gold], direction: 135)>Couleurs</h2>
<span *loader(bloom)></span>
<section *fly(up, distance: 60, on: view)>…</section>
{if $ouvert}<div @in=*iris @out=*fade>…</div>{end}
<@document *ripple></@document>
```

<details>
<summary>🎓 <b>Pour débutants</b> — qu'est-ce qui se passe quand j'écris <code>*neon</code>&nbsp;?</summary>

Le compilateur lit le mot et ses réglages, vérifie qu'ils existent et que leurs valeurs sont permises, puis branche l'effet sur la balise. Une faute (effet inconnu, réglage faux, effet sur une balise qui ne peut pas le porter) arrête la construction et cite le fichier, l'effet et la ligne de sa balise : `*titre (ligne 6) : effet inconnu` (sur `<@document>`, la ligne n'est citée que pour une faute d'alias pointé (`*ripple.rouge`)). Quand la balise apparaît dans la page, l'effet se pose : son style, et ce qu'il faut pour réagir (la souris, le défilement, une minuterie). Quand la balise disparaît — un `{if}` qui se referme, une ligne retirée d'un `{for}`, le composant détruit —, l'effet se retire avec elle. Vous n'avez rien à nettoyer. Un effet qui attend encore son fichier ou son composant ne reste pas non plus : l'attente s'arrête à ce moment-là.

Seuls les effets que vous écrivez partent dans le fichier de votre appli : un projet qui n'écrit que `*neon` n'emporte pas le code des autres, et un projet sans effet n'emporte rien.

</details>

## Écrire un effet

- `*nom` seul : l'effet, avec ses réglages par défaut.
- `*nom(valeur)` : une valeur **sans son nom** règle le **réglage principal** de l'effet — la couleur du néon, l'inclinaison maximale du tilt, le style du loader (en gras dans les tableaux plus bas). `*neon(#f0f)` = `*neon(color: #f0f)`.
- `*nom(valeur, réglage: valeur)` : les autres réglages se nomment, **dans l'ordre qu'on veut** : `*neon(size: 2, #f0f, flicker: true)`. Une seule valeur sans nom est permise, où qu'elle soit dans la liste.
- Plusieurs effets sur une balise : `<h1 *rainbow *bounce>`. Le même effet deux fois sur une balise est refusé.
- Un effet appelle toujours les méthodes DOM de la balise elle-même : un composant qui définit `focus`, `contains` ou `getBoundingClientRect` ne voit jamais un effet les appeler.
- **La transition et le transform de l'auteur restent.** Un effet qui anime sa balise par une transition — `*lift`, `*stack`, `*iso`, `*extrude`, `*clay`, `*neon`, `*zoom` (sur la balise elle-même), `*highlight`, `*outline`, `*cycle`, et chaque enfant de `*focus` — garde celle que la balise avait déjà (`.carte { transition: background-color .3s }`, ou celle d'un autre de ses effets : une carte `*lift` dans un `*focus` glisse encore) ; la sienne s'y ajoute. Elle est relevée à la pose de l'effet, et tout est rendu au retrait. `*magnet` et les enfants de `*dock` bougent par une animation de `translate` et de `scale` qui s'ajoute à ce que la feuille leur donne à chaque instant : le `transform` de l'auteur (une rotation, un centrage) et sa transition restent, et ses propres `translate` et `scale` aussi — un badge centré par `translate: -50% -50%`, une icône réduite par `scale: .8` (ce qu'écrit Tailwind 4) gardent leur place et leur taille au repos, l'effet s'y ajoute, même quand une classe ou un `:hover` de l'auteur les change ensuite (`hover:-translate-y-0.5`, `hover:scale-110`) ; rien n'en reste au retrait. Un navigateur qui ne sait pas ajouter une animation à ce que la feuille donne (`composite: 'add'`, Safari avant la 16) laisse `*magnet` et `*dock` immobiles, plutôt que de remplacer le `transform` de l'auteur.
- Un réglage qui attend **un effet** (le `fx` de `*delta`, de `*guard`, de `*offline`) le prend écrit comme sur une balise, réglages compris : `*delta(fx: *scramble(20))` ; `none` pour aucun.
- **L'arrondi des cadres.** Les effets qui dessinent un cadre autour de leur balise — `*flash`, `*guard`, `*pulse`, `*border`, `*spotlight`, `*gauge`, `*stack`, `*glass`, `*lift` — ont un réglage `radius` : l'arrondi des coins, en px (`*pulse(radius: 12)`). La balise le prend tant que l'effet est posé, et le cadre le suit ; sans lui, celui de la balise.
- Une valeur est **fixe** — un nombre (`12`, `1.5`), une durée (`300ms`, `1.5s`, `0`), une couleur CSS (`#0ff`, `rgb(0, 255, 255)`, `magenta`), `true`/`false`, un mot de la liste permise (`up`, `zoom`…), une **liste** entre crochets (`[#f0f, #0ff, gold]` pour des couleurs, `[Coder., 'Designer, web.']` pour des mots) — ou **une variable écrite telle quelle** : `$couleur`, `$$accent`, `$reglages.taille`. Des guillemets sont acceptés (`'zoom'`) ; une virgule entre parenthèses, crochets ou guillemets ne coupe pas la valeur ; dans une valeur entre guillemets, un antislash garde le guillemet qui le suit (`chars: 'a\'b'` vaut `a'b`). Un réglage texte respecte la longueur de sa règle, comptée en caractères : `axis` de `*weight` (`string 4..4`) en prend quatre, ni plus ni moins.
- Pas de commentaire entre les parenthèses : un `// …` ou un `/* … */` dans les réglages d'un effet arrête le build, qui le cite. Un texte entre guillemets n'est jamais un commentaire : une adresse s'écrit donc entre guillemets (`image: '//cdn/a.png'`). Sans guillemets, `https://exemple.fr/a.png` — nommée (`image: https://…`) ou seule, au réglage principal (`*behind(https://…)`) — et un chemin comme `/img/*.png` passent aussi, mais une adresse sans protocole (`//cdn/a.png`) peut être lue comme un commentaire.

```html
<h1 *neon($couleur, size: $taille)>Soirée</h1>
<input *shake($erreur)>
<span *cycle($metiers)>Développeur</span>
```

Une variable est lue quand l'effet se pose, puis **suivie** : `$couleur` change, le néon change avec elle, sans repartir de zéro ; un réglage de comportement (l'inclinaison du tilt, la cadence du glitch) relance l'effet avec sa nouvelle valeur. La règle du réglage s'applique aussi à la variable : un nombre hors de sa plage est ramené à la borne, une valeur impossible est écartée (l'effet reprend sa valeur par défaut) — avec un message dans la console pendant le développement. Une couleur, une liste de couleurs ou une valeur CSS tenue par une variable peut venir d'une donnée de l'utilisateur : elle ne charge jamais une adresse. `url(`, `image(`, `image-set(`, `@import`, une barre oblique inverse, `;`, `{`, `}` ou des parenthèses qui ne s'équilibrent pas la font écarter de la même façon ; la découpe de `*hologram` (`zone`), posée dans le CSS, suit la même règle. Un texte tenu par une variable — le `suffix` de `*count`, les `chars` de `*scramble`, le `text` de `*offline` ou de `*guard`, un sélecteur (`to` de `*travel`, `of`), une adresse donnée exprès (`frames` de `*scrub`, `server`) — ne va jamais dans le CSS : il passe tel quel, parenthèse seule et barre oblique inverse comprises (`$fin = 'Bravo :)'`). Un effet donné avec ses réglages par une variable (`$effet = { fx: 'glitch', s: { color: $couleur } }`, pour le `fx` de `*delta`, de `*guard` ou de `*offline`) suit la même règle, quelle que soit la voie qui mène ses réglages au CSS : tous ses réglages en texte ou en liste — ses variables CSS, tous ceux d'un effet CSS de l'appli, ce que l'effet pose lui-même dans un style (les `colors` de `*gradient`, de `*mesh`, la `zone` de `*hologram`), une image écrite `url(…)` — sont écartés de la même façon, avec le même message ; seuls ses textes de la page (`text`, `chars`, `prefix`, `suffix`, `separator`, `decimal`, `words`, un sélecteur…) passent tels quels. Une liste s'y donne en tableau ou en texte à virgules : un objet qui n'est pas un tableau (`{ 0: 'red', length: 1 }`, « semblable à une liste ») est écarté de même. Une image (`image`, `mask`, `back`, `logo`) y prend la voie d'une image écrite en réglage : une adresse, `data:` comprise, posée entre guillemets. Ses nombres et ses textes bornés suivent les plages du catalogue, comme écrits par une variable sur la balise : un nombre hors de sa plage est ramené à la borne (`{ fx: 'count', s: { pad: 99 } }` donne `pad: 12`), un nombre donné en texte est lu (`'5'`), un texte trop court ou trop long est écarté (le `prefix` de `*count` : 8 caractères au plus), avec le même message ; le build n'ajoute cette table des plages au cœur que si une page nomme un effet par une variable. Son nom, comme un nom seul (`$effet = 'glitch'`), doit être celui d'un effet de l'appli qui se joue une fois, comme écrit en clair (`*delta(fx: *scramble(20))`) : un nom inconnu, un effet qui ne se joue pas une fois (`magnet`, `particles`), ou un nom que tout objet JavaScript porte (`constructor`), est écarté de la même façon, avec le même message. Un calcul ne s'écrit pas entre les parenthèses : passe par une variable dérivée (`$taille = $grand ? 3 : 1`).

Tout est vérifié **à la compilation**. Le build s'arrête et dit quoi écrire : effet inconnu (avec la suggestion la plus proche : `*neom` → `*neon`), réglage inconnu (avec la liste des réglages de l'effet ; un nom qui n'a jamais été un réglage reste un réglage inconnu, même écrit comme une propriété d'objet : `constructor`, `toString`), un espace avant les réglages (`*neon (#0ff)` : ils se collent au nom ; le message cite la ligne, sur `<@document>` ou `<@window>` comme sur une balise), un guillemet double jamais refermé dans les réglages, valeur fixe hors de sa règle (avec ce qui est permis : `max = 99 — permis : float 0..45`, `axis = abcde — permis : string 4..4`), deux valeurs sans nom, réglage écrit deux fois, des accolades (`{…}`) ou un calcul entre les parenthèses, `*neon=…` au lieu de `*neon(…)`.

## Le vocabulaire commun

Les effets partagent les mêmes mots pour les mêmes idées :

- **`on` — quand l'effet agit**, pour un effet qui a un moment à choisir — la liste des réglages de chaque effet, plus bas, dit s'il l'a. Un effet sans `on` agit tant qu'il est posé : `*gauge` suit sa valeur, `*parallax` le défilement, `*longshadow` reste. `always` : tout le temps — sauf que ses minuteries se reposent hors de l'écran (à 100 px près) et repartent au retour : `*cycle` reprend alors à son premier mot ; un fond animé (`*noise`, `*mesh`, `*path`, `*gradient`, `*crt`) ne s'arrête pas : le navigateur ne le peint pas hors de l'écran, mais l'animation continue ; `hover` : au survol ; `view` : quand un cinquième de ce que la balise peut montrer est à l'écran, mesuré au conteneur qui la rogne (`overflow` autre que `visible`, zone qui défile, sous `zoom`, contenu d'un composant ou glissé dans un `<slot>`) — plus grande que l'écran ou que ce conteneur, un cinquième de la surface qu'elle y occupe ; une balise qui tient dans l'écran et que seul son bord coupe est jugée sur elle-même ; une balise `position: fixed` ou `absolute` n'est rognée que par l'ancêtre qui la contient (une `fixed` : celui qui la retient — `transform`, `translate`, `rotate`, `scale` ou `offset-path`, même à une valeur neutre comme `rotate: 0deg`, `perspective`, `filter`, `backdrop-filter`, `transform-style` autre que `flat`, `content-visibility` autre que `visible`, un `contain` de mise en page ou de dessin, ou un `will-change` sur l'une de ces propriétés, `contain` compris ; `container-type` et `will-change: offset-rotate` ne retiennent rien) ; `click` : au clic ; `load` : dès l'apparition, même hors de l'écran. Le sens exact suit la nature de l'effet :
  - un effet **qui boucle** (`*gradient`, `*float`, `*spin`…) tourne tant que la condition tient — pendant le survol, tant que la balise est à l'écran ; `click` et `load` jouent **un** tour ;
  - un effet **à état** (`*neon`, `*lift`, `*outline`…) est allumé ou éteint : allumé pendant le survol, dès l'arrivée à l'écran (il y reste), ou basculé à chaque clic ;
  - un effet **qui se joue** (`*scramble`, `*stagger`, `*count`…) se joue une fois par déclenchement : `view` le joue quand la balise **entre** à l'écran — plus bas dans la page, il attend qu'on y arrive —, `load` le joue tout de suite, que la balise soit visible ou non ;
  - `success`, `error` : à la fin réussie, ou ratée, de l'action de la balise — un envoi de formulaire, une demande au serveur (cf. [Réussite et échec](#réussite-et-échec--on-success-on-error), plus bas). Un effet qui se joue se joue, un effet qui boucle fait un tour, une transition posée directement arrive ; un effet à état n'a pas de moment.
- **`where`** — la partie de la balise qui porte l'effet : `text` (les lettres), `box` (le cadre), `both`.
- **`direction`** — le sens d'un mouvement, d'un balayage : un mot (`right`, `left`, `up`, `down`, et les diagonales `up-right`, `up-left`, `down-right`, `down-left`) ou un **angle** en degrés, compté comme pour un dégradé CSS — `0` vers le haut, `90` vers la droite, `135` vers le bas à droite. Un balayage part du côté opposé : `*shine(direction: 135)` part du coin haut gauche. Quelques effets n'ont que quatre sens (un remplissage, un défilé) : leur tableau le dit.
- **`origin`** — le point d'où part l'effet : `center`, `top`, `bottom`, `left`, `right`, `top-left`…, `x% y%` (`20% 80%`), et `pointer` — le point sous la souris — pour un effet qui sait le suivre.
- **`order`** — l'ordre dans lequel partent les lettres d'un effet de lettres : `right`, `left`, `center`, `edges`, `random`.
- **`zone`** — pour un effet qui suit le défilement (`on: scroll`), la bande de l'écran où il se joue : deux hauteurs, en % (`0%` en haut de l'écran, `100%` en bas) ou en mots (`top`, `center`, `bottom`). L'effet part quand le **haut de la balise** passe la première, il est fini à la seconde : `zone: 60% 40%` le joue autour du milieu de l'écran, `zone: bottom center` du bas jusqu'au milieu. Sans `zone` : du bas de l'écran (le haut de la balise y entre) jusqu'au milieu (son milieu y arrive). Dans une boîte qui défile, l'écran est cette boîte.
- **`angle`** — une orientation fixe, en degrés (celle d'une ombre, d'un relief, d'un motif).
- **`colors`** — une liste de couleurs, `[#f0f, #0ff, gold]`.
- **`delay`**, **`duration`**, **`speed`** — l'attente avant de partir, la durée d'un passage, la durée d'un cycle.
- **`easing`** — la courbe du mouvement : `linear`, `ease`, `ease-in`, `ease-out`, `ease-in-out` ; une transition prend aussi `cubic-bezier(…)` et les courbes de `µeasing` (`bounce-out`, `elastic-out`…).

## Les effets, par famille

Chaque effet se règle et s'essaie en direct dans l'éditeur des effets de la documentation du site : un aperçu, un contrôle par réglage, et la ligne de code qui suit. Dans votre appli, en développement, le panneau d'inspection (`µconsole`, onglet « Effets ») montre les effets posés et les règle à chaud — cf. [34 · Déboguer](34-deboguer.md). Les composants prêts à l'emploi (`<@@carousel>`, `<@@deck>`, `<@@tabs>`, `<@@menu>`, `<@@clock>`, `<@@knob>`, `<@@number>`, `<@@progress>`, `<@@cube>`) sont au chapitre [30 · Modules cœur](30-modules-coeur.md).

- `order` des effets de lettres (`*scramble`, `*stagger`, `*bounce`, `*rainbow`) : l'ordre dans lequel les lettres partent — `right` de gauche à droite, `left` de droite à gauche, `center` du centre vers les bords, `edges` des bords vers le centre, `random` au hasard. `*stagger(move)` fait glisser chaque lettre dans le sens de `direction` (un mot ou un angle). Un `<br>` du texte reste un saut de ligne : les lettres passent à la ligne au même endroit (la mise en forme en ligne, elle — `<b>`, `<em>`, une couleur —, n'est pas recopiée sur les lettres). Les copies du texte de `*split`, `*glitch` et `*neon` passent aussi à la ligne à un `<br>`, et seulement là : les sauts de ligne de la mise en forme du gabarit (un titre écrit sur plusieurs lignes) n'y ajoutent rien, pas même une ligne vide en tête ; dans une balise qui garde ses espaces (`white-space: pre`, `pre-wrap`, `break-spaces`), la copie les garde aussi, comme ses sauts de ligne. Le texte que lit un effet ne compte jamais ce qu'un autre effet ajoute plus bas : `<p *stagger>Prix <b *count>42</b></p>` se lit « Prix 42 ».
- `*shine(where: text)`, `*gradient` : `direction` est le sens du balayage ou du défilé, un mot ou un angle — `*shine(where: text, direction: 135)` balaie en diagonale, du coin haut gauche au coin bas droit. `*split` coupe le texte dans le sens de `direction` : `right`, deux moitiés haute et basse ; `45`, une coupe en biais.
- `*glitch`, `mode` : sans réglage, l'effet choisit seul — `text` sur une balise qui porte son texte (les lettres tremblent, deux calques colorés se décalent), `box` sur un composant, une image, un champ (la balise entière est secouée).
- `*count` : le nombre s'écrit sans séparateur dans la balise (`12480`, `3.5`) ; `separator` (les milliers) et `decimal` choisissent ceux de l'affichage (`*count(separator: '.', decimal: ',')`). Une espace devient l'espace fine insécable de la typographie. Le nombre affiché ne passe jamais à la ligne, et la balise prend sa largeur (celle du plus large, du départ ou de l'arrivée) : séparateurs, `prefix` et `suffix` ne débordent pas sur le texte qui suit. La place du nombre est reprise quand une police arrive après la pose, dans tous les navigateurs (WebKit compris). Une largeur minimale que votre feuille donne à la balise (`min-width: 6em`, pour une colonne de chiffres alignés) est gardée : la place du nombre ne la réduit jamais. Le nombre se lit dans le texte de la balise : le premier seul (« 3/10 » vaut 3, « Étape 2 sur 5 » vaut 2), avec ses séparateurs de milliers (« 12 480 », « 1,234 » avec `separator: ','`) ; le signe moins typographique (« −5 », celui qu'écrivent `toLocaleString()` en suédois, en finnois ou en norvégien) se lit comme un tiret. Le signe suit le nombre arrondi : un compte qui passe par zéro n'écrit jamais « -0 ». Un réglage d'écriture tenu par une variable (`prefix`, `suffix`, `pad`) réécrit le nombre affiché sans recompter ; `duration`, `easing` et `delay` valent au compte suivant ; `separator` et `decimal` (la langue qui change) rejouent le compte, comme `from`, `on` et `style`.
- `*count(style: flip)` : le nombre en **volets**, comme sur un panneau d'aéroport. Chaque chiffre est une carte qui **bascule** quand il change : l'effet fabrique lui-même ses cartes, vous n'écrivez que `<span *count(style: flip)>{$n}</span>` — aucune balise de plus, aucun style à poser. Seules les cartes dont le chiffre change basculent (129 → 130 : les deux dernières, la carte du 1 ne bouge pas) ; le reste du nombre (séparateurs, `prefix`, `suffix`) s'écrit en texte entre les cartes. Le compte est celui de `*count` — `duration`, `from`, `easing`, `delay` et `on` gardent leur sens — et les cartes suivent le nombre à mesure qu'il change : une carte déjà en train de basculer garde le dernier chiffre demandé pour sa bascule suivante, de sorte qu'un compte rapide fait défiler les chiffres sans empiler de bascules. Pour un compteur qui bat la seconde ou qu'on incrémente, `duration: 0` change les cartes tout de suite, sans compte intermédiaire. Un nombre qui gagne un chiffre (9 → 10) fait arriver une carte en basculant, un nombre qui en perd un (100 → 99) rend la sienne ; la balise garde la place du plus large des deux, comme sans volets. `pad: 2` écrit les zéros de tête (`07`), avec ou sans volets : un compte à rebours à deux cartes par unité. `speed` est la durée d'une bascule (400ms), `background` le fond des cartes et `color` leur chiffre : `$$count-background` et `$$count-color` les règlent pour toute l'appli (cf. [Les régler pour toute l'appli](#les-régler-pour-toute-lappli--les-variables-de-thème)). La taille des cartes suit celle du texte (`font-size`) et sa hauteur de ligne (`line-height`). Le texte écrit reste dans la balise, lisible par un lecteur d'écran ; les cartes sont décoratives (cachées aux lecteurs d'écran, leurs chiffres ne sont jamais du texte). Avec « réduire les animations », le chiffre change sans bascule. Le code des volets n'est dans le fichier de votre appli que si une page écrit `style: flip` (et celui des zéros de tête que si une page écrit `pad`).

```html
<span *count(style: flip, duration: 0, pad: 2)>{$secondes}</span>
<span *count(style: flip, separator: '.', suffix: ' €')>{$total}</span>
<span *count(style: flip, background: #1b2330, color: #fff)>{$visites}</span>
```

- `*longshadow` : `length` est la longueur de l'ombre fixe, et la plus grande quand elle fuit le pointeur ; `light: true` ajoute la lampe qui suit la souris près de la balise ; elle reste dans la zone de la balise — son premier ancêtre qui rogne et la contient vraiment (une balise `position: fixed` n'a pas de zone : la fenêtre ; une balise `position: absolute`, seulement son bloc conteneur et ce qui le contient) —, son halo s'arrête au bord de la zone, coins arrondis compris. Seule la zone la plus proche est suivie ; un `clip-path` est rogné en rectangle.
- `*dissolve` : le texte reste effacé ; un nouveau déclenchement le fait revenir puis se désagréger encore. La poussière prend la couleur de chaque lettre, et reste attachée au texte : si la page défile, elle part avec lui.
- `*stagger`, `unit: word` : les mots arrivent l'un après l'autre, plutôt que les lettres. `on: scroll` : l'arrivée suit le défilement — rien quand la balise entre par le bas, tout quand elle atteint le milieu, et retour en arrière si l'on remonte : `*stagger(fade, unit: word, on: scroll, step: 150ms, duration: 300ms)` allume une phrase mot à mot pendant la lecture — un `step` plus long que `duration`, et les mots s'allument un à un. `zone` choisit où, dans l'écran : `*stagger(fade, unit: word, on: scroll, zone: 60% 40%)` allume les mots pendant que le haut du texte passe de 60 % à 40 % de la hauteur de l'écran, autour du milieu. `distance` est le chemin de chaque lettre, pour le style `move` seulement : `fade`, `zoom`, `flip`, `blur`, `rotate` ne se déplacent pas. Au défilement, sans `step` ni `easing` écrits, les mots s'allument un à un, d'un pas régulier ; `opacity: .2` laisse ceux à venir en gris (l'opacité de départ de chaque lettre ou mot, avec tous les styles).
- Le « Text Reveal » (Magic UI, Apple) : un texte **collé** au milieu de l'écran pendant qu'on fait défiler une section plus haute que lui, les mots qui s'allument un à un, le gris sur ceux de la fin si l'on s'arrête en route. Une balise collante (`position: sticky`, elle ou un parent) lit son avancée sur la section qui la porte : 0 quand le haut de la section atteint le haut de l'écran, 1 quand son bas en atteint le bas (`zone` n'y compte pas) — `<section class="lecture"><div class="colle"><p *stagger(fade, unit: word, on: scroll, opacity: .2)>…</p></div></section>`, avec `.lecture { height: 200vh }` et `.colle { position: sticky; top: 0; height: 100vh; display: grid; place-items: center }` : le texte, au milieu de l'écran, pose l'effet sur sa propre balise, dans la boîte qui centre.
- `*annotate` se trace sous les yeux, d'un trait qui tremble (toujours de la même façon pour le même texte), en `strokes` passages ; un texte en ligne sur plusieurs lignes : `underline` et `strike` suivent chaque ligne. Le trait se dessine dans les pixels de la page : un parent qui la réduit (`transform: scale(.5)`) le réduit avec elle, et il couvre toujours tout le mot. Il se redessine quand le mot change de place ou de taille, y compris quand une police web arrive après la pose (Chrome, Firefox et Safari).
- `*cycle` : le texte de la balise est le premier mot (il reste dans la page prérendue), `words` donne les suivants : `<span *cycle([applis, logos])>sites</span>` ; une balise en ligne prend la largeur du mot affiché. Un lecteur d'écran entend tous les mots : celui de la balise, puis les suivants. Le passage d'un mot à l'autre, `style` — `slide` : le nouveau mot pousse l'ancien dans le sens de `direction` ; `flip`, `fade`, `blur`, `zoom` (le relais dure `duration`) ; `frame` : un cadre lumineux s'ouvre sur le mot puis se referme (`delay` : le temps où il reste fermé, `speed` : celui de son passage) — `outside` dit ce qu'on voit du mot hors du cadre : `hidden` (défaut), rien ; `hollow`, le mot en creux (un contour d'un pixel, qui se lit mieux sur un grand titre) ; `visible`, le mot entier, le cadre ne fait que passer dessus ; `type` : une machine à écrire — après une ligne vide de `delay`, le mot se tape lettre à lettre, reste, puis s'efface, le tout en `speed` ; `cursor: false` retire son curseur. `color` colore le cadre, le creux et le curseur. `*cycle.frame` et `*cycle.typewriter` règlent ces deux styles tout prêts : un mot toutes les 3,5 s.
- `*circular` : chaque caractère, espaces compris, prend sa part du cercle — un texte qui finit par une espace (`DÉFILER • DÉFILER • `) referme la boucle ; la balise prend la taille du cercle.
- `*tracking(-0.2)` : un `spacing` négatif fait partir les lettres serrées l'une sur l'autre.
- `*gradient` : les lettres sont une fenêtre sur un fond qui défile ; entre elles, le fond de la page. Sans réglage, le dégradé `colors` glisse dans le sens de `direction`, ses bandes perpendiculaires au défilé. `*gradient('paysage.jpg')` y montre une image, qui va et vient dans le sens de `direction` : une valeur écrite sans nom qui est une image (un fichier, une adresse finie par son extension, `url(…)`) va à `image`, un mot de motif va à `pattern`, le reste aux couleurs ; une image tenue par une variable s'écrit avec son nom (`image: $photo`). Image introuvable : le dégradé prend le relais, la console le dit. `size` (la taille du fond, en % de la balise ; 200 par défaut avec une image) ou `angle` (l'angle des bandes du dégradé, quand il n'est pas celui du défilé) font du dégradé une tuile qui défile sur l'axe de `direction` — droite, gauche, haut ou bas, une autre direction prend l'axe le plus proche : des bandes perpendiculaires au défilé bouclent, des bandes de biais vont et viennent. `pattern` remplit les lettres d'un motif aux couleurs `colors` — `stripes` des rayures, `dots` des pois, `waves` des vagues, `checks` un damier —, qui avance dans le sens de `angle` (sans lui, celui de `direction`) ; une image l'emporte sur le motif. `outline` et `width` ajoutent un contour aux lettres. Le texte reste sélectionnable et lu normalement ; un navigateur sans `background-clip: text` garde la couleur des lettres. Deux préréglages donnent les rendus tout faits : `*gradient.knockout` (un dégradé rose, violet, cyan qui défile vers la gauche, ou l'image donnée : `*gradient.knockout('paysage.jpg')`) et `*gradient.texture` (des rayures en biais ; `*gradient.texture(dots)` : des pois).
- `*weight` : chaque lettre s'épaissit à l'approche de la souris, dans le rayon `radius`, de `min` à `max`. Il faut une police variable (axe `wght`, ou celui de `axis` — avec `axis: wdth`, `min` et `max` valent par défaut 75 et 125, les bornes de la largeur ; un autre axe prend celles de la graisse tant qu'ils ne sont pas écrits) ; sans elle, `fallback` décide — `auto` : des graisses par crans si la police en a, sinon un étirement ; `bold` ; `stretch` ; `none`. `idle` : sans souris, une vague parcourt le mot toute seule, en `speed`. Une police qui arrive après la pose (un `@font-face` encore en route, ou un `font-family` changé vers une police qui se charge) refait la mesure : le mode suit la police présente, dans tous les navigateurs, WebKit compris.
- `*spoiler` cache le texte de la balise jusqu'au clic (`on: hover` : jusqu'au survol) — `grains` : des grains qui grouillent ; `blur` ; `bar` : une barre pleine ; `pixels` : de gros pavés. Tant qu'il est caché, le texte n'est ni lisible ni sélectionnable, et la balise se comporte comme un bouton (Entrée et Espace la révèlent). `again` : un second clic recache. `revealed` se tient par une variable ; la révélation émet l'événement `mjs:reveal`. Posez-le sur un `<span>` pour ne cacher que quelques mots : s'il court sur plusieurs lignes, le texte continue de couler et chaque ligne est couverte. Une police qui arrive après la pose déplace les lignes : le calque les suit, dans tous les navigateurs (WebKit compris). Tant que le texte est caché, un lien ou un bouton qu'il contient ne s'atteint pas au clavier. Au doigt, rien ne survole : avec `on: hover`, un toucher révèle le texte et le suivant le recache.
- `*spoiler` caché : ce qui n'est pas du texte est caché aussi — une image, une vidéo, un SVG, le fond d'un `<mark>` ou d'un `<code>` (chaque balise du contenu devient transparente) ; avec `blur`, les images, vidéos, SVG et toiles sont cachés, le texte reste flou. La recherche du navigateur (Ctrl+F) trouve encore le texte caché : `hidden="until-found"` le sortirait de la mise en page, et le calque n'aurait plus rien à couvrir.
- `*annotate(on: always)` : le trait se retrace sans fin, après une pause `every` (3s).
- `*marquee` : avec `on: hover`, `view` ou `click` (ou un tour fini), le défilé est au repos : une seule copie du texte se voit, la seconde n'apparaît que pendant le défilement. Sous « réduire les animations », le texte ne défile pas : une seule copie, au début de la balise.
- `*marquee` sur une balise qui n'a que des éléments pour enfants (des images, des cartes dans un `<div>`, un `<ul>` : aucun texte à elle) : ce sont eux, les vrais, qui défilent, rangés en une ligne (une colonne avec `up` ou `down`) séparés par `gap`, et recopiés autant de fois qu'il faut pour couvrir la balise plus un tour (un de plus avec `drag`, car la main s'ajoute à la dérive ; pas avec `on: scroll` ni `axis: both`, où rien ne dérive). Les copies sont de vraies copies, qu'on touche comme l'original. La copie d'un composant ModularJS est son miroir vivant (celui de `µclone el, mirror: true`) : une instance montée, avec son script, ses reffets et son `µmount`, qui partage l'état de l'original — cliquer « +1 » dans une copie fait monter le compteur partout, ce qu'on tape dans son champ arrive à l'état commun —, et dont la balise garde son nom : le CSS qui la vise s'y applique. `@@isMirror` y vaut `true` : un `µmount` qui charge des données ou lance une minuterie le fait aussi dans chaque miroir, une requête de plus par copie, sauf s'il s'en garde (`return if @@isMirror`). Un composant rendu par le gabarit d'un miroir est une instance neuve, qui reçoit ses props du rendu du miroir ; un composant glissé entre les balises d'un composant de la bande est, dans la copie, un miroir lui aussi. Une feuille collée ou retirée par `µ.adoptSheet` dans l'ombre de l'original (même avant que la bande n'existe) l'est aussi dans ses miroirs. Un composant ModularJS dont le module n'est pas encore arrivé (chargé à la demande) n'entre dans les copies qu'à son arrivée. Le reste de la bande (textes, liens, images, boutons, champs) est recopié balise par balise et suit, au plus une fois par image, ce qui change dans les nœuds d'origine (un texte, un attribut, un nœud ajouté ou retiré), ce qu'on tape ou coche dans un champ (un bouton radio que le choix d'un autre décoche compris) et la remise à zéro (`form.reset()`, un bouton `type="reset"`) d'un formulaire posé dans la bande ou qui la contient ; celle d'un formulaire rangé dans l'ombre d'un composant de la bande n'est pas suivie d'elle-même. Ce qui ne change aucun nœud n'est pas suivi de lui-même : la valeur d'un champ posée par un script, la position d'une zone qui défile ; les copies les rattrapent quand elles se refont (la taille de la piste change, un enfant arrive ou part). Une balise recopiée se comporte comme l'original : un bouton, une ligne d'une liste `{for}` (quatre listes imbriquées au plus) jouent le gestionnaire que le gabarit leur donne (`@click`, `@submit`…), sur la copie (`e.currentTarget` est l'élément de la copie) ; un lien mène où il mène, sa confirmation et sa méthode comprises (`@confirm`) ; ce qu'on tape dans un champ recopié arrive à l'état comme dans l'original (un champ lié), ou à l'original (un champ libre), et l'original comme chaque copie le montrent ; un formulaire recopié est un vrai formulaire, qui s'envoie avec ses champs, et dont le bouton `type="reset"` remet l'original à zéro. Un écouteur posé par un script sur un original (`addEventListener`) ne vaut pas pour ses copies : écrivez-le dans le gabarit. Un identifiant que cite une balise de la bande (le `for` d'une étiquette, `aria-labelledby`, `aria-describedby`, le `list` ou le `form` d'un champ…) devient, dans chaque copie, un identifiant propre à la copie (`nom` devient `nom-mjs-copy-1`, `nom-mjs-copy-2`…), et les références de la copie le suivent : l'étiquette d'une copie nomme le champ de sa copie et y met le focus quand on la clique ; une référence à une balise hors de la bande reste telle quelle, et un identifiant que rien ne cite dans la bande n'est pas recopié. Les copies n'ont pas de gestionnaire en ligne comme `onclick`, et `autofocus`, `accesskey` et `contenteditable` n'y sont pas recopiés : une zone éditable du contenu ordinaire se montre dans les copies, on n'écrit que dans l'original. Un composant recopié, lui, est un miroir où l'on écrit comme dans l'original : ce qu'on tape dans l'éditeur d'une copie (`<@@editor>`) arrive à l'état commun, l'original et chaque copie le montrent, et Ctrl+Z l'annule partout. Un champ que son formulaire n'accompagne pas dans la copie (la bande est posée dans le formulaire, ou c'est un bouton radio sans formulaire) n'a ni nom ni obligation : il ne part pas une seconde fois avec le formulaire de l'original, et ne l'empêche pas de partir. Le miroir d'un composant associé au formulaire (un module de saisie du cœur comme `<@@number name>` ou `<@@checkbox name>`, un composant `@formAssociated`) en sort de même : sa balise reçoit `form=""`, qui ne désigne aucun formulaire, et le champ caché d'un module du cœur la suit ; il garde son nom, une prop de l'état qu'il partage avec l'original. Les autres balises gardent leurs attributs, `name` compris : une icône lue par son nom (`<sl-icon name="…">`) s'affiche dans chaque copie, et un `<slot name>` recopié garde son nom — placé après l'original, il ne reçoit rien. Le reste se recopie comme par `cloneNode` : un composant d'une autre bibliothèque est construit dans chaque copie (il y montre son état de départ), une `<iframe>` charge sa page une fois par copie, et un `<canvas>` reste vide dans les copies (son dessin n'est pas recopié). Au clavier et à la lecture d'écran, les copies sont comme le reste de la page : la touche Tab passe par chaque copie, le survol, l'appui et la sélection du texte y sont réels, et le lecteur d'écran lit la bande autant de fois qu'elle a de copies ; avec `drag`, tirer la piste ne clique jamais. La grille ou le flex de la balise ne s'applique plus aux enfants, la piste les range. Une balise vide n'a rien à défiler : aucune copie. Un texte garde son défilé d'avant — du texte nu, avec ou sans balises en ligne dedans (`<b>`, `<a>`, `<span>`, `<br>`…) —, tant qu'on ne lui demande ni `drag`, ni `on: scroll`, ni `axis: both`.
  - `drag: true` : on tire la piste à la souris ou au doigt ; elle garde son élan puis reprend son allure, et un clic de moins de 5 px reste un clic sur l'enfant visé. Le défilement de la page reste libre dans l'autre axe.
  - `on: scroll` : la piste avance avec le défilement de la page (et des boîtes qui défilent autour d'elle) et recule quand on remonte ; `speed` y devient un rapport : un tour pour 100 px de défilement par seconde de `speed` (12s : un tour pour 1 200 px). `reverse: true` va dans l'autre sens que `direction` : deux colonnes voisines, l'une des deux en `reverse`.
  - `axis: both` : une nappe sans bord dans les deux sens, le contenu répété en damier ; elle ne bouge que tirée (`drag` y est mis d'office) ou, avec `on: scroll`, en hauteur.
  - `unit` : le défilé des balises (la piste, ses copies) n'est envoyé à l'application que si une de ses poses de `*marquee` en a besoin ; une application qui ne fait défiler que du texte est plus légère de plus d'un kilo-octet. `auto` (par défaut) : le compilateur regarde la balise. Un texte (fixe, interpolé, avec ou sans balises en ligne) n'en a pas besoin ; une balise qui n'a que des éléments pour enfants, une liste `{for}`, un `<slot>`, un composant, du HTML inséré tel quel (`{{ }}` ou `@html=!{…}`) le demandent d'eux-mêmes. Un blanc compte pour rien, même écrit `&nbsp;`. Dans le doute, le défilé part, même s'il ne sert pas toujours : une interpolation (`{$message}`) à côté de balises (elle peut être vide), une entité que le compilateur ne lit pas à coup sûr, un composant accompagné de texte, des morceaux de tableau (`<tr>`, `<td>`) hors d'un tableau. `child` le demande vous-même : pour une balise qu'un script remplit (elle est vide dans le gabarit, le compilateur ne peut pas le deviner). Sans lui, des balises ajoutées par un script ne défilent pas en production, sauf si une autre pose de l'application fait déjà envoyer ce défilé : à défaut, elles restent à leur place, et c'est leur texte seul, recopié sur une ligne, qui défile par-dessus elles. `mjs dev` vous le dit dans la console, une fois par balise créée (une balise recréée par un `{if}`, ou chaque ligne d'un `{for}`, prévient à son tour), quand elle fait défiler des balises que sa pose ne demande pas : qu'elles soient là dès la pose (un `@attach` les a ajoutées avant) ou qu'elles arrivent après. Si votre HTML est mal imbriqué au point que le navigateur le range autrement que vous ne l'avez écrit (un `<h3>` dans un `<h2>`, un `<a>` dans un `<a>`, un `<form>` dans un `<form>`, un `<button>` dans un `<button>`, un `<li>` dans un `<li>`, des morceaux de tableau hors d'un tableau), le compilateur ne voit pas la même balise que le navigateur : la production peut laisser les balises en place là où le développement les fait défiler. `mjs dev` vous le dit de la même façon, et `*marquee(unit: child)` règle la question. `drag`, `axis: both` et `on: scroll` demandent déjà ce défilé. Une balise qu'un script ajoute rejoint le défilé : elle change de parent, la piste devient le sien ; pour la retirer, écrivez `noeud.remove()` (un `balise.removeChild(noeud)` lève une erreur, la balise n'est plus son parent). Un composant qu'un script ajoute est connecté deux fois : il entre dans la page, puis dans le défilé.
  - Hors de l'écran, rien ne tourne ; sous « réduire les animations », ni dérive ni élan, la main et le défilement restent.
- Un script qui réécrit le texte d'une balise (`textContent`, `innerHTML`) ne coupe pas les effets qui travaillent le texte de leur balise : ils repartent sur le nouveau texte, avec les mêmes réglages, comme pour un texte lié par `{$x}`. Un effet qui pose son décor comme enfant de la balise (les étincelles de `*sparkles`, la toile à gratter de `*scratch`, la jauge de `*gauge`, les barres de `*skeleton`…) est reposé sur le nouveau contenu quand un script réécrit celui de la balise (`textContent`, `innerHTML`, `replaceChildren`), avec les mêmes réglages, comme s'il venait d'y être posé : une carte à gratter est de nouveau couverte, un texte caché le reste, les barres d'un squelette reviennent. Un script qui ne fait que vider une balise qui ne contenait que le décor (`innerHTML = ''`) le laisse perdu jusqu'à l'écriture suivante, qui le repose ; le calque de `*border` (son liseré posé avec `*spotlight`, sa dentelle, son trait) revient, lui, tout de suite. Ce qui n'est pas posé dans la balise n'est pas reposé : le décor d'une balise qui est un composant vit dans l'ombre du composant (une réécriture interne l'emporte sans retour) ; le bandeau de `<@document *offline>` est posé dans le `<body>`, que la reprise ne suit pas ; la scène de `*react(stage: true)` et le calque de `*heatmap(show: true)` partent avec le contenu et ne reviennent pas ; l'aura de `*particles(mode: aura)` est posée à côté de la balise, qu'une réécriture ne touche pas : elle continue, il n'y a rien à reposer.

- Une transition se pose sur le **cycle de vie** d'une balise qu'un `{if}`, un `{for}` ou un `{key}` ajoute ou retire : `@in=*fly(up, distance: 200)` à son entrée, `@out=*fade` à sa sortie, `@transition=*slide` aux deux — cf. [10 · Transitions & animations](10-transitions.md).
- Posée **directement** sur une balise, elle se joue selon `on` : `view` (défaut) — la balise attend, cachée, d'arriver à l'écran ; `once: false` la fait ressortir et revenir à chaque passage —, `scroll` — l'animation suit le défilement : le passage de la balise à l'écran (réglé par `zone`, la bande de l'écran où elle se joue), ou une plage de la page, `range: 0 1000px` —, `load` — dès l'apparition —, `hover` — cachée au repos, elle entre quand la souris arrive sur son parent et sort quand elle le quitte (`of: '.carte'` désigne à la place l'ancêtre le plus proche qui vérifie ce sélecteur ; `once`, `range` et `zone` n'y changent rien ; cf. [10 · Transitions & animations](10-transitions.md)). `*crossfade` ne se pose que sur le cycle de vie. Les réglages d'un groupe (`duration`, `delay`, `easing`, `fallback`) sont ceux de sa première pose : en développement, une pose suivante du même groupe qui en écrit d'autres est signalée dans la console, une fois par groupe — donnez-leur les mêmes réglages, ou un autre `group`.
- `easing` : les courbes CSS, `cubic-bezier(…)`, et celles de `µeasing` écrites avec des tirets — `bounce-out`, `elastic-out`, `back-in-out`, `cubic-out`… `*fly` et `*swipe` vont dans tous les sens (un mot ou un angle), `*volet`, `*reveal`, `*flip`, `*cube`, `*turn`, `*bars` dans quatre.
- `*shared(clé)` : l'élément partagé d'une **transition de page** (`@viewTransition`, cf. [17 · Router](17-router.md)). Deux balises qui portent la même clé de part et d'autre d'une navigation — la vignette d'un produit dans la liste, sa photo dans la page du produit — sont appariées : la première glisse et grandit jusqu'à la place de la seconde, le reste de la page fond. `{for p in $produits by id}<img src={p.photo} *shared(p.id)>{end}` dans la liste, `<img src={$produit.photo} *shared($produit.id)>` dans la page du produit. La clé (obligatoire) est un nombre ou un mot, fixe ou variable ; `group` sépare deux éléments de la même fiche (`*shared(p.id, group: titre)`). Deux balises de la même page avec la même clé : le navigateur saute la transition.
- `*ink` — la balise apparaît à travers un masque qui s'étale ; à la sortie, le même masque se rejoue à l'envers. Vingt styles, dessinés dans le navigateur (aucun fichier à charger) : `burn` (le papier brûle), `frost` (du givre), `rain` (la pluie sur une vitre), `cells` (une mosaïque), `cracks` (des fissures), `ripple` (des ondes), `scribble` (un gribouillage), `petals` (une fleur), `glitch` (un écran qui décroche), `topo` (des lignes de niveau), `maze` (un labyrinthe), `blots` (des taches d'encre), `brush` (des coups de pinceau), `wash` (une aquarelle), `smoke` (une fumée), `drip` (des coulures), `dots` (une trame de points), `shards` (des éclats), `swirl` (un tourbillon), `tear` (une déchirure). `soft` : la douceur du bord ; `count` : le nombre de taches, de coups, de points ; `seed` : une autre variante ; `direction` (`brush`, `wash`, `drip`, `dots`, `tear`) et `origin` (`blots`, `smoke`, `shards`, `swirl`) : d'où ça part. **Votre masque** : `*ink(image: 'masques/logo.png')` — n'importe quelle image, lue par sa luminosité : le sombre apparaît d'abord, le clair en dernier (`invert: true` renverse). Une image illisible (adresse fausse, autre site sans autorisation) : la balise arrive en fondu, et la console le dit. Sous une politique de sécurité stricte (CSP), le masque demande `img-src data:`.
- Les classiques des logiciels de présentation et de montage : `*fly(left, blur: 6, skew: 30)` arrive à toute vitesse, penchée et floue ; `*scale(axis: x)` s'étire de côté ; `*rotate(-90, start: 0)` grandit en tournant ; `*iris(shape: box)` — `box`, `diamond`, `cross` — ouvre un rectangle, un losange, une croix ; `*wheel(4)` découvre la balise par quatre rayons à la fois.

- `*pixels` — `fill` : des carreaux de couleur remplissent la balise, dans le désordre ; `explode` : une nappe de carreaux la couvre et vole en éclats (`cover: true` : par-dessus le contenu) ; `strip` : un rideau de fines barres ; `mosaic` : l'image de la balise se découpe, tournoie et se recompose ; `swap` : l'image laisse place à une autre (`image`), carreau par carreau. L'image de `mosaic` et `swap` est le fond de la balise, sinon sa première `<img>`. Le jeu (remplissage, explosion…) commence quand les carreaux naissent : une balise cachée puis montrée, ou pas encore mise en page à la pose, le joue au moment où elle apparaît. Sous « réduire les animations » (réglage du système), aucun carreau ne se joue : la balise passe d'un coup à son état final.
- `*pulse`, `where: text` : le halo bat autour des lettres plutôt qu'autour du cadre ; `direction: in` : l'anneau revient vers la balise.
- `*shine` : `every` règle la cadence des passages pour `on: always` et `on: view` ; écrit avec `on: hover`, les passages se suivent ainsi pendant le survol, et la souris qui sort coupe celui en cours ; `direction` (un mot ou un angle) le sens du reflet. `where: text` : le reflet balaie les lettres, en ligne droite et à vitesse constante, et le texte prend la couleur `ink` — la balise ne change ni de place ni d'affichage ; `width` reste la largeur du reflet en % de la balise. `*shine.shimmer` : un texte « en chargement », gris, que le reflet balaie sans fin.
- Une balise en ligne (`<span>`, `<a>`) ne se déplace pas, ne tourne pas et ne rogne pas ce qui la déborde : les effets qui animent sa boîte — `*marquee`, `*shine`, `*parallax`, `*float`, `*spin`, `*tilt`, `*glitch`… — la passent en `display: inline-block` le temps de l'effet, et lui rendent son affichage quand il se retire.
- `*ripple`, `origin` : `pointer` (défaut) — l'onde part du point touché —, ou un point fixe (`center`, `top-left`, `20% 80%`). `*confetti`, `direction` : le sens de la gerbe (`spread`, son ouverture).
- `*smoke` : `count` règle la densité de la fumée, de 1 à 100 : trois bouffées vivantes par point au plus, soit 60 au défaut (20) et 300 à `count: 100`, le plafond ; elles naissent au fil de leur vie (`duration`) — une souris qui ne s'arrête pas garde une traînée continue. « Réduire les animations » : aucune bouffée. C'est un effet lourd : en mode économe, il en fait naître trois fois moins.
- `*attention` — `tada` : grossit en tremblant ; `wobble` : tangue de côté ; `jello` : tremble comme une gelée ; `heartbeat` : deux battements de cœur ; `swing` : se balance, pendue par le haut ; `rubber` : s'étire comme un élastique ; `blink` : clignote ; `headshake` : fait « non » de la tête ; `jump` : saute et rebondit ; `pop` : gonfle un instant ; `wiggle` : un petit balancement autour du centre, de l'amplitude `angle`. `on: always` rejoue l'appel sans fin, avec la pause `every` entre deux ; `on: hover` ou `on: view` avec `every` écrit : l'appel se répète pendant le survol, ou tant que la balise est à l'écran, et la souris qui sort (la balise qui quitte l'écran) le coupe. `*attention.wiggle` : le balancement, une demi-seconde, qui revient toutes les deux secondes tant que la souris est dessus. Comme `*float`, `*spin` et `*shake`, l'appel s'ajoute au `transform` de l'auteur (`animation-composition: add`) : un badge centré par `translate(-50%, -50%)` le fait sur place et le retrouve tel quel une fois fini ; un navigateur trop ancien pour cette propriété remplace ce transform le temps de l'animation.

- `*tilt` : `depth` fait flotter les enfants directs de la balise devant elle (la parallaxe) ; `slide` fait glisser le fond de la balise avec la souris.
- `*spotlight` — `where: both` : un halo dedans et un liseré qui s'allume au bord ; `fill` : le halo seul ; `border` : le liseré seul, comme une lampe torche. `origin` : là où la lumière se tient — `pointer` (le défaut), elle suit la souris ; un point (`bottom-left`, `20% 80%`), elle y reste sans la souris, allumée d'office avec `on: always`, ou le temps du survol : une lueur qui part d'un coin et déborde dans la boîte (le voile suit toujours la souris). `glow` : la portée du halo dans la boîte, en px — sans lui, celle du liseré (0,72 fois `size`). `every` : allumée, la lumière s'allume par instants, un éclat à chaque durée (« réduire les animations » : allumée sans éclat).
- `*zoom`, `origin` : le point d'où le contenu grossit — `center`, `top-left`, `20% 80%`…, ou `pointer`, le point sous la souris, qui suit. Une balise qui porte du texte, ou dont aucun enfant ne peut grossir seul, grossit tout entière. Les calques posés sur la balise par d'autres effets (le coin de `*peel`…) ne grossissent pas avec son contenu. Le grossissement passe par la propriété `scale` : il s'ajoute au `transform` de l'auteur, et une balise placée par une translation (un badge centré par `translate(-50%, -50%)`) grossit à sa place.
- `*hologram` : un reflet irisé par-dessus la balise, qui suit la souris et dérive tout seul en son absence (`speed`) — `rainbow`, `foil` (fines rayures métallisées), `galaxy` (nuées et points brillants), `prism` (facettes), `gold`. `colors` donne votre palette, `blend` le mode de fusion du reflet, `glare` ajoute un éclat blanc sous la souris ; `on: hover` : visible au survol seulement. Si un script réécrit le contenu de la carte (`textContent`, `innerHTML`, `replaceChildren`), le reflet revient de lui-même, au plus tard au mouvement suivant de la souris sur la carte ; une carte agrandie reste agrandie. Les autres styles (`frame`, `curtain`, `night-sky`, `frost`, `lattice`, `opal`, `streaks`, `rays`… : la liste du tableau ci-dessus) sont les finitions d'une carte à collectionner. Eux seuls lisent `image` (le motif gravé de la carte), `mask` (l'image qui dit où le motif brille) et `back` (le dos d'un zoom `spin`) : avec un style simple (`rainbow`, le défaut, `foil`, `galaxy`, `prism`, `gold`), ces trois réglages sont ignorés et aucune image n'est chargée (en développement, la console le dit, une fois par balise). `zone` donne la fenêtre de l'illustration, une forme CSS écrite telle quelle, comme pour `clip-path` : `zone: inset(10% 8% 53% 8%)` pour un rectangle (haut, droite, bas, gauche), `zone: polygon(16% 16%, 92% 16%, 92% 47%, 8% 47%, 8% 24%)` pour un coin coupé ; `circle(…)`, `ellipse(…)` et `path(…)` sont permis aussi, et une variable peut porter la forme (`zone: $fenetre`). `curtain`, `night-sky`, `rays-window`, `frost` et `lattice` y découpent leur reflet ; `frame` brille tout autour (sans `mask`), ce qui demande un `inset(…)` ou un `polygon(…)`, les seules formes dont le cadre se déduit. Sans `zone`, la fenêtre est toute la carte.
- `*hologram`, la gravure : `image` est la **gravure** d'une carte, un dessin (des chevrons, des symboles, un grain) que la lumière fait briller. Avec `frame`, sans gravure, l'éclat suit la souris mais reste lisse : aucun dessin ne brille ; avec elle, les traits de la gravure brillent sous la lumière. Même style, même fenêtre, avec et sans gravure — seule `image` change :

  ```html
  <div class="carte" *hologram(frame, zone: inset(10% 8% 53% 8%))><img src="carte.webp" alt="Une carte"></div>
  <div class="carte" *hologram(frame, image: 'gravure.webp', zone: inset(10% 8% 53% 8%))><img src="carte.webp" alt="Une carte"></div>
  ```

- `*hologram`, les images de motif : celles que MJS livre avec les styles de carte (paillettes, grain, ciel, anneaux, vagues, disques, bandes) sont les images du site d'origine de l'effet, de Simon Goellner (simeydotme) : [github.com/simeydotme/pokemon-cards-css](https://github.com/simeydotme/pokemon-cards-css).
- `*flipcard` se pose sur une balise à **deux enfants** : le premier est le recto, le second le verso — `<div *flipcard><div>recto</div><div>verso</div></div>`. `on` : `hover`, `click`, `view`, ou `none` quand une variable commande seule : `*flipcard(on: none, flipped: $ouverte)`. La face cachée est inerte (ni clic, ni lecture). La balise devient une grille : les deux faces prennent la place de la plus grande. Au clavier, l'effet place dans la carte une commande à elle, « Retourner la carte » dans la langue de la page (« Flip the card » en anglais ; la clé `mjs.fx.flip` de votre dictionnaire la change), que Tab atteint avant le contenu : cachée hors du focus, elle apparaît en haut à droite de la carte quand elle le reçoit, et se dit pressée quand le verso est montré (`aria-pressed`) ; c'est le premier enfant de la carte : une règle de votre feuille qui visait une face par sa position vise désormais autre chose (`:first-child` vise la commande, `:nth-child(2)` le recto ; `:last-child` reste le verso) — visez vos faces par une classe. La carte, elle, ne se dit jamais bouton : elle porte souvent des contrôles (un lien au recto, un bouton au verso), qu'un bouton ne peut contenir — un lecteur d'écran les lirait tous dans son nom, ou les tairait. Une balise focalisable d'elle-même (`<button *flipcard>`), ou à laquelle vous avez donné un `tabindex`, ne reçoit pas de commande : elle répond elle-même à Entrée et Espace. Avec `on: hover`, le focus de la commande retourne la carte, Entrée et Espace la basculent (un lien ou un bouton de la carte garde son action), un clic sur la commande aussi — sauf le clic qui suit le focus qui vient de la retourner, ce que fait un lecteur d'écran en l'activant : elle reste retournée, le clic suivant la remet —, Échap la remet, et elle reste retournée tant que le focus est dans le verso ; avec `on: click`, Entrée et Espace sur la commande la retournent, et un clic sur un lien, un bouton, un champ ou une étiquette de la carte garde son action sans la retourner (un formulaire au verso se remplit sans que la carte ne revienne au recto), même dans un composant (un `<@@select>`, un champ en composant) ; un clic sur l'une des deux faces la retourne, même si elle porte un `tabindex`, comme un clic sur un élément d'une face à `tabindex="-1"` (un titre que votre script focalise après le retournement).
- `*scratch` : une couche à gratter, à la souris ou au doigt, par-dessus le contenu de la balise — une couleur, un dégradé (`colors`) ou une image (`image`), avec un mot dessus (`text`, dans la couleur `ink`). Quand la part grattée atteint `threshold`, le reste s'efface et la balise émet `mjs:scratch`. `revealed`, tenu par une variable, découvre tout ; repassé à faux, il remet la couche. Une couleur de `colors` que le navigateur ne sait pas lire (venue d'une variable) est ignorée, et la console le dit. Seul le doigt qui commence le geste gratte : un second doigt posé pendant ce temps est ignoré.
- `*peel` : le coin `corner` de la balise se soulève — `size` au repos, `grow` quand l'effet est actif (`on`) — et montre `under` (une couleur) ou `image` ; `color` est le dos de la page.
- `*focus(grow: 1.1)` : l'enfant survolé grandit et passe au-dessus de ses voisins ; quand la souris le quitte, il y reste le temps de rétrécir (`duration`).

### Bordures

| Effet | Ce qu'il fait | Réglages — le principal en premier, défaut entre parenthèses |
|---|---|---|
| `*border` | une bordure animée : liseré en dégradé et son halo, dentelle, trait qui court | **`style`** gradient, wave, run (`gradient`) · `colors` liste de couleurs (`[#ffbc00, #ff0058]`) · `color` couleur · `width` int 1..40 · `glow` int 0..200 (30) · `angle` int 0..360 (45) · `animate` bool (false) · `speed` durée · `delay` durée (0s) · `radius` int 0..999 |

- `*border` — `gradient` : un liseré en dégradé et son halo (`glow`), qui peuvent tourner autour de la balise (`animate`) ; `wave` : les quatre bords se découpent en dentelle qui défile, dans la couleur du fond derrière la balise (ou `color`) ; `run` : un trait de lumière court le long des quatre bords, l'un après l'autre. Posé avec `*spotlight` sur la même balise, le dégradé lui laisse les deux pseudo-éléments de la balise : son liseré et son halo se dessinent dans un calque posé dans la balise (dans le composant, sur un composant), et chacun des deux effets se voit comme s'il était seul ; `*spotlight` retiré, le dégradé revient dans les pseudo-éléments de la balise. Un script qui réécrit le contenu de la balise (`textContent`, `innerHTML`, `replaceChildren`) emporte ce calque, comme la dentelle de `wave` et le trait de `run` : ils reviennent aussitôt sur le nouveau contenu, avec leurs réglages, même quand le script n'a fait que vider la balise ; un script qui réécrirait la balise à chaque retour du calque ne fige pas la page : au-delà de vingt retours dans une même tâche, le calque revient à la tâche suivante ; emporté encore plus de vingt fois à ce retour, il attend l'écriture suivante.

Les balises restent (leur classe, leur style : la mise en page tient), chaque texte ou valeur devient une barre qui scintille (un titre, une barre large ; une valeur seule dans un paragraphe, trois lignes), une image garde sa boîte, un composant devient un bloc, une boucle trois lignes. Les réglages de l'effet (`color`, `shine`, `speed`, `radius`) s'appliquent. Refusé si la branche d'attente est déjà écrite. Un `{await}` **sans** branche d'attente prend cette silhouette de lui-même (cf. « Ce que MJS fait de lui-même », plus bas).
- `*skeleton` sur la balise d'un **composant** (`<@carte *skeleton>`) : tant que son code n'est pas arrivé, sa balise montre la silhouette de son HTML (tirée au build), qu'il attende un contenu ou non ; elle part juste avant son premier rendu. Elle paraît une fois en place les composants encore en route placés avant elle, dans la page ou dans les composants qui la contiennent : arrivés après, ils la pousseraient.
- `*skeleton` sur une balise ordinaire : ses barres sont muettes, et, le temps qu'elles sont là, la balise dit aux lecteurs d'écran que son contenu est en route (`aria-busy="true"`, sauf une valeur que vous avez écrite) ; elle le retire avec elles. `height` donne sa hauteur à la silhouette — un nombre en px, ou une longueur CSS en px, %, em, rem, vw ou vh (`120`, `8rem`, `100%`) — et ses barres se la partagent, chacune d'au moins 14 px : `*skeleton(lines: 1, height: 200)` est un bloc de 200 px. Sans `height`, la silhouette a la hauteur de ses barres (14 px chacune, 10 px entre elles). Une hauteur nulle ou négative (`height: 0`, `height: -20`, `0px`) ne donne rien à la silhouette : la construction vous le dit par un avertissement (`lint.syntax`). Un pourcentage se rapporte à la hauteur écrite de la balise ; sans elle, il ne vaut rien. Tenu par une variable, `height` suit sur place. Sur un bloc `{await}` et sur la balise d'un composant, la silhouette est tirée du HTML : `lines` et `height` n'y changent rien.
- `*loader` se pose sur une balise vide : `<span *loader(bloom)></span>`. Les styles — `dots` : un anneau de billes qui s'éteignent tour à tour ; `steps` : un cadre qui bascule par quarts ; `plus` : une croix dont les bras pivotent ; `neon` : un arc de néon qui s'ouvre et se referme ; `trio` : trois anneaux de couleur ; `3d` : un anneau en dégradé dans une dalle en relief (`color2` : la fin du dégradé) ; `bloom` : une fleur de carrés ; `spiral`, `galaxy`, `cross` : des points lumineux sur des rayons. Sans `color` ni `speed`, chaque style garde ceux de sa démo. Le dessin est muet ; la balise annonce le chargement aux lecteurs d'écran : une région `role="status"` (sauf un rôle que vous avez écrit), qui reçoit, une image après sa pose, un texte qu'ils sont seuls à lire — « Chargement », dans la langue affichée, ou votre `aria-label` s'il est écrit (une région vivante annonce ce qui change en elle, pas son nom).

- `*magnet`, `ring: true` : un anneau suit la souris et grossit autour de la balise survolée.
- `*iso` : les deux côtés du cube reprennent le fond de la balise, un peu assombri.
- `*orbit` : chaque enfant de la balise prend sa place sur le cercle, à égale distance des autres ; un enfant ajouté ou retiré (un `{for}`) et tout se répartit de nouveau. Un centre fixe (un logo) se pose à côté, dans un parent commun. `upright: false` : les enfants tournent avec le cercle.
- `*dock` : la balise garde sa taille, la rangée s'élargit autour de son centre ; `axis: y` pour une colonne (les enfants grandissent vers la droite). L'enfant sous la souris reste le plus gros quand la barre défile ou qu'un parent la réduit (`transform: scale(.5)`, `zoom`) — la portée (`range`) se réduit avec elle — et un enfant ajouté, retiré ou remplacé pendant le survol compte dès le mouvement suivant. Les calques posés sur la barre par d'autres effets (`*mesh`, `*ripple`…) ne sont pas des enfants : ils ne grossissent pas et ne poussent pas la rangée.
- `*pointer` : le disque vit au-dessus de la page, mais pas au-dessus de la couche du dessus — une boîte de dialogue ouverte par `showModal()`, un `popover` ouvert, une partie de la page en plein écran —, que rien ne dépasse. La souris y entre : le disque s'éteint, et le curseur du système y reste visible, même avec `hide: true`, au-dessus d'un composant qu'elle contient aussi ; il revient à la sortie. Posé DANS l'une d'elles (une zone à l'intérieur d'une boîte de dialogue ouverte par `showModal()`), il y vit : le disque s'y voit, sous la souris, même quand la boîte est centrée par un `transform` (`translate(-50%, -50%)`), et avec `hide: true` le curseur du système y est caché, liens compris.
- `*path` — la balise suit un tracé. **Un tracé tout fait** : `*path(wave)`, `loop`, `circle`, `infinity`, `zigzag`, `spiral`, `heart`. **Le vôtre**, écrit comme l'attribut `d` d'un `<path>` SVG : `*path('M10 100 C 60 20, 100 20, 145 80')` — en pixels depuis le coin du parent positionné, ou dans le repère `viewbox` (`viewbox: '0 0 290 160'`), que l'effet met alors à l'échelle du parent. **Un tracé déjà dessiné** : `*path(from: '#trace')` lit le `<path id="trace">` du même composant, et la balise le suit là où il est à l'écran. `rotate` fait tourner la balise avec la courbe (`angle` : un décalage), `alternate` fait l'aller-retour, `repeat` compte les parcours (0 : sans fin), `start` et `end` bornent la portion parcourue ; `on: scroll` : l'avancée suit le défilement.

- `*kenburns` se pose sur le **cadre** de l'image — `<figure *kenburns><img …></figure>` — ou sur une balise qui a une image de fond : le cadre ne bouge pas, l'image dedans avance. Au-delà de `distance` = (zoom − 1) × 50, le bord de l'image se découvre.
- `*filter` — `on: rest` : filtrée au repos, les vraies couleurs au survol (des logos en noir et blanc qui se colorent) ; `hover` : l'inverse. `amount` dose le filtre, de 0 à 1 ; `duotone` peint les ombres de la première couleur de `colors`, les lumières de la seconde. `spot` : le diamètre, en px, de la zone sous la souris où la balise se montre sans son filtre (`soft` : son bord doux ; `smooth` : son retard). `ring: true` borde la zone d'un cercle de 2 px (sa couleur : `color`, blanc sans elle), qui vient et part en fondu ; `near: true` la montre dès que la souris approche de la balise, à moins de son rayon et de son bord, avant d'y entrer, et la retire d'un coup, sans fondu — loin de la balise, rien n'est écrit ; `parallax` (de 0 à 1) fait glisser la balise et la zone nette avec la souris, de cette part de l'écart au centre de la balise, et elles restent où la souris les a laissées (la balise glisse par un filtre SVG : sa boîte et sa place ne bougent pas ; sans animation, réglage du système, rien ne glisse). `*filter.lens` réunit tout cela sur un texte : flou de 10 px, net sous une loupe cerclée de 200 px de diamètre qui suit la souris de près. Dans un parent qui rogne ou qui défile sans être positionné, la zone positionne ce parent (`position: relative`) le temps du survol, puis le rend tel quel ; s'il ne peut pas l'être sans déplacer ce qu'il contient (une balise posée en absolu qui le prendrait pour repère, des décalages `top`, `left`… écrits sur lui), la zone ne se pose pas et la console le dit en développement : mettez la balise dans un bloc en `position: relative`, à l'intérieur de ce parent.
- `*filter`, les réglages fins — `brightness`, `contrast`, `saturate` (1 : inchangé), `hue` (en degrés), `grayscale`, `sepia`, `invert` (de 0 à 1), `blur` (px), `opacity`, `shadow` (une ombre portée CSS : `shadow: '0 8px 20px #0008'`). Ils se cumulent entre eux et avec un style : `*filter(lomo, contrast: 1.2)`. Écrits sans style, aucune ambiance ne s'ajoute : `*filter(brightness: 1.2, hue: 40)`.
- `*filter` dans WebKit : la balise filtrée suit ce qui change autour d'elle. Ombre, contour et enfants qui débordent sont relus quand une classe ou un style change sur la balise, sur un enfant ou sur un ancêtre (variable CSS de `body` comprise), quand un enfant est ajouté ou retiré, au survol d'un ancêtre ou de la balise, au focus, et à chaque image tant qu'une animation ou une transition court ; la trame, la lumière du vignettage, les lignes, les pavés et la bande de `tiltshift` suivent la balise même quand une ombre, un contour ou un enfant sorti élargit la région du filtre ; les ombres de texte et celles des enfants ne sont pas vues. Limites : une balise tournée, en miroir, sous `zoom` ou dans un ancêtre mis à l'échelle ne compte pas ses enfants dans l'encre ; à deux pixels d'appareil ou plus, l'encre peut avoir 1 pixel d'écart sur 1 à 2 % des ombres ; une règle CSS modifiée sans changement d'attribut n'est pas relue.
- `*filter`, les ambiances neuves : `polaroid`, `lomo`, `kodachrome`, `technicolor`, `cyberpunk`, `sunset`, `night`, `nightvision`, `thermal`, `xray`, `newsprint`, `bleach`, `cross`, `pastel`, `matrix`. Les effets spéciaux et leurs réglages : `posterize` (`levels`), `threshold` (`threshold`), `sharpen`, `emboss`, `edges` (`strength`), `chromatic` (`shift`), `pixelate` (`size` ; quand la boîte n'est pas un multiple de `size`, le dernier pavé, partiel, est rempli : la page ne se voit jamais à travers), `grain` (`strength`, `size`), `halftone` (`size`), `vignette` (`strength`, `radius`), `tiltshift` (`strength`, `band`), `bloom` (`strength`, `radius`), `ripple` (`frequency`, `scale`), `scanlines` (`gap`) ; `duotone` prend deux couleurs, ou trois (ombres, tons moyens, lumières). `amount` dose le tout, de 0 à 1. Les styles neufs passent par un filtre SVG : leur passage au survol est immédiat, sans fondu. Cinq ambiances (`lomo`, `technicolor`, `cyberpunk`, `sunset`, `cross`) demandent `img-src data:` sous une politique de sécurité stricte.
- `*blend` — trois usages. Seul, `<h1 *blend(difference)>` fond la balise avec ce qu'il y a derrière elle : le titre s'inverse sur ce qu'il recouvre. Avec `color` ou `colors` (un dégradé, à l'angle `angle`), un calque de couleur est fondu avec la balise : `<img src="photo.jpg" *blend(multiply, color: #ff4fa3)>`. Avec `image`, **deux images fusionnées** : `<img src="a.jpg" *blend(screen, image: 'b.jpg')>` ; `fit` et `position` cadrent la seconde image, `opacity` la dose, `order: under` la passe dessous : la balise entière, fond et texte, est alors fondue par-dessus ; le calque couvre sa boîte, coins arrondis compris, et ce qui en déborde (une ombre, un enfant) reste tel quel — sauf l'ombre de `*filter(shadow: …)` et le décalage de `*chromatic` posés sur la même balise, rognés à sa boîte. Sur une `<img>`, ou avec `order: under`, la fusion passe par un filtre CSS : comme tout filtre, la balise devient le cadre de ses enfants en `position: fixed` ; sur une balise en ligne (`<span>`, `<a>`), le calque couvre la boîte qui englobe ses lignes, sans coins arrondis (`display: inline-block` les lui rend). Un dégradé et des coins arrondis passent par une image `data:` : sous une politique de sécurité qui la refuse, les coins restent carrés, le dégradé prend sa première couleur, et la console le dit. Les seize modes : `normal`, `multiply`, `screen`, `overlay`, `darken`, `lighten`, `color-dodge`, `color-burn`, `hard-light`, `soft-light`, `difference`, `exclusion`, `hue`, `saturation`, `color`, `luminosity`. La position de la boîte est relue quand la page grandit ou se redimensionne, quand une image ou une police finit de se charger, au retour de l'onglet et à la fin d'une transition ou d'une animation de la balise ou d'un parent, jamais à chaque image ; tant que la balise est transformée (penchée par `*tilt`, tournée, agrandie), le calque garde le cadre du repos. Une marge changée par une classe, ou une balise déplacée par la transition d'une voisine sans que la page change de taille, n'est relue qu'à l'un de ces événements. `*filter`, `*liquid`, `*chromatic` et `*blend` se cumulent sur la même balise : `*blend` passe en dernier.
- `*liquid` : au survol (`on`), la balise ondule comme sous l'eau — `strength` la force, `rest` la part gardée au repos, `frequency` la finesse des vagues. Au repos, la déformation gardée reste figée : les vagues ne bougent que pendant que l'effet est actif (survolé), et repartent d'où elles s'étaient arrêtées. `*chromatic` : les canaux de couleur se séparent de `gap` pixels au repos, de `grow` quand l'effet est actif, dans la direction `angle` ; `mode: cmy` pour cyan, magenta, jaune. Ces deux effets, comme `*filter`, écrivent la propriété `filter` de la balise : deux d'entre eux sur la même balise, et la console vous dit d'en poser un sur une balise englobante. `*blend`, lui, se cumule avec chacun.
- `*crt` : un calque par-dessus la balise — lignes de balayage tous les `lines` pixels, scintillement (`flicker`), bande qui descend (`roll`), bords assombris (`vignette`), teinte de phosphore (`tint`), halo du texte (`glow`).
- `*reflect` : le reflet ne prend pas de place dans la page, prévoyez une marge sous la balise. `size` est la part reflétée avant le fondu complet ; `blur` le floute, `water` le fait onduler. Dans une liste à clé qui se réordonne, le reflet suit sa balise ; une liste de plusieurs centaines de lignes se pose, se réordonne et se redimensionne en une seule passe de mise en page, sans la refaire ligne par ligne ; une ligne retirée du DOM emporte son reflet. Sur un composant, ou sur une balise qui en contient un (même arrivé après la pose), `blur` et `water` ne sont pas possibles là où il n'existe pas de `-moz-element` (Chromium, Safari) : leur copie ferait naître un second composant ; le reflet reste simple, et la console le dit.
- **Une image en réglage** (`image` de `*blend`, `*gradient`, `*scratch`, `*peel`, `*ink`) s'écrit par son chemin, tel quel (`*gradient(image: 'photo.jpg')`, relatif au dossier source ou à un dossier de `assetDirs`), ou par son adresse : le build trouve le fichier et prépare ses variantes de largeur, sans `µimage` ni `µasset` à écrire. L'effet charge la variante taillée pour la balise (la plus petite qui couvre sa largeur × la densité de l'écran — une image cadrée en `cover` dans une balise plus haute qu'elle : la largeur qu'elle y prend, quand le build connaît ses dimensions —, sinon l'image d'origine), ou pour la largeur de la fenêtre quand la balise n'est pas encore affichée au moment où il se pose (cf. [35 · Images](35-images.md)) ; l'image n'est demandée, et l'effet posé, que lorsque la balise approche de l'écran (à 200 px) : une balise loin sous le premier écran ne télécharge rien d'ici là, quel que soit `on`, et une balise déjà à l'écran charge son image tout de suite (une pose qui échoue à l'approche ne laisse rien sur la balise, et l'erreur s'affiche dans la console comme pour toute pose d'effet qui échoue) ; une variable marche aussi. Pour choisir vous-même les largeurs de cette seule image, `µimage('photo.jpg', 320, 640)` reste possible ([35 · Images](35-images.md)). Une adresse écrite telle quelle tient en 2000 caractères : une image en `data:` plus longue passe par une variable ou par un fichier (`'masque.png'`).

- `*parallax`, `speed` — `0.5` : la balise prend du retard sur la page ; `1` : elle reste immobile à l'écran ; `-0.5` : elle file plus vite ; `origin: page` compte le glissement depuis le haut de la page (une bande fixe qui glisse), `view` depuis le milieu de l'écran. Dans une boîte qui défile (`overflow: auto` ou `scroll`, dont le contenu déborde), c'est la plus proche qui compte : son défilement (`origin: page` : 0 tant qu'elle n'a pas défilé), son milieu (`view`). Elle est reconnue à chaque image, même devenue défilable après la pose. Une enveloppe qui ne déborde pas (`overflow-x: hidden`) ne compte pas : la page anime la couche.
- `*scrollprogress` : une barre qui avance avec le défilement — de la balise elle-même (`source: self`, sur une balise qui défile : `overflow: auto`), ou de la page (`source: page`, la barre est fixée au bord de la fenêtre). `place` : `top`, `bottom`, `left`, `right` ; `origin: center` la fait grandir depuis son milieu ; `track` colore le rail, `colors` en fait un dégradé, `duration` lisse le mouvement. Sous Chromium, la barre est pilotée par le navigateur pour la page ou une balise qui défile ; sur une balise qui ne défile pas, elle reste vide, comme partout. `duration` tenu par une variable suit sur place. Un lecteur d'écran l'annonce « Progression de la lecture » (« Reading progress » en anglais) ; la clé `mjs.fx.progress` du dictionnaire du projet change ce nom (cf. [29 · i18n](29-i18n.md), « Libellés du framework »).

- `*delta` suit le nombre écrit dans la balise (`<td *delta>{$cours}</td>`) : rien au premier affichage ; à chaque changement, la balise clignote dans la couleur du sens (`up`, `down`), une flèche à droite du nombre (hors du flux : le nombre ne bouge pas), et le nouveau nombre s'écrit par `fx` — `*count` (défaut) : il compte de l'ancienne valeur à la nouvelle ; `none` : d'un coup ; ou un autre effet qui se joue une fois, avec ses réglages (`*delta(fx: *scramble(20))`, `*delta(fx: $effet)`). Il s'écrit comme avec `*count` (`separator`, `decimal`, `prefix`, `suffix`). La place du nombre est reprise quand une police arrive après la pose, dans tous les navigateurs (WebKit compris).
- `*gauge` : la valeur est le nombre écrit dans la balise (`<span *gauge>{$volume}</span>`), ou `value` ; la plage, `min` et `max` écrits, sinon celle de la variable dans le bloc `<vars>` (`$volume int 0..100`), sinon 0 à 100. `style` — `fill` : la balise se remplit derrière son texte ; `line` : un trait le long de son bord ; `ring` : un anneau. `colors` : la couleur suit la valeur, du bas au haut de la plage (`[#22c55e, #eab308, #dc2626]`). La jauge glisse d'une valeur à l'autre (`duration`, `easing`). Elle n'a pas de réglage `on` : posée, elle suit sa valeur.
- `*guard` se pose sur un champ lié (`<input value=!{$age} *guard>`) — et se pose **de lui-même** sur tout champ lié à une variable typée (cf. « Ce que MJS fait de lui-même », plus bas) : la règle est celle de sa variable dans le bloc `<vars>` (`$age int 1..120`), sinon les contraintes du champ (`min`, `max`, `maxlength`, `pattern`, `required`). Pendant la frappe, le champ n'est jamais réécrit : une valeur hors de la règle est retenue (la variable garde la dernière bonne). Une pause sur une telle valeur (`delay`, 1 s par défaut ; `0` : dès la frappe) : le champ fait « non » de la tête (`fx`, `*shake` par défaut) et une bulle dit ce qui est permis (`text` pour l'écrire vous-même ; `place`, `color`, `duration`), sans toucher à ce qui est tapé — on peut s'arrêter au milieu d'un nombre. À la sortie du champ, ou sur Entrée, une valeur hors de la plage est ramenée à la borne, une autre rendue à la dernière bonne, avec la secousse et la bulle. `silent: true` : ni secousse ni bulle, la valeur seulement ramenée à la sortie. Dans une liste à clé qui se réordonne, la bulle suit son champ ; un script qui retire le champ de la page (lui ou un parent) ferme sa bulle. Quand la fenêtre change de taille ou se tourne, la bulle ouverte se replace contre son champ. Elle reste dans la largeur de la fenêtre, à 8 px de ses bords, et ne fait jamais déborder la page de côté : contre le bord droit, elle glisse vers l'intérieur ; avec `place: right`, quand la place manque à droite du champ, elle se pose sous lui. Pendant que le champ tremble, la bulle reste à sa place de repos. Quand le champ porte une transformation 2D simple, elle est calculée sans toucher au style du champ. Quand le champ a une transformation 3D (`perspective()`, `rotateX`/`rotateY`, `translateZ`), un `transform-box` autre que celui par défaut, ou un ancêtre transformé ou en perspective, le champ est mesuré avec ses transformations neutralisées le temps d'une lecture : une transition ou une animation de votre part sur `transform`, `translate`, `rotate` ou `scale` est alors interrompue. `offset-path` n'est pas pris en compte : la bulle se décale.
- `*flash` éclaire la balise quand son contenu change (`on: change`, défaut ; aussi `load`, `click`, `hover`, `view`) — `style` : `outline` (un contour), `fill` (un fond), `glow` (une lueur) ; `radius` arrondit l'éclair (`*flash(style: fill, radius: 6)` sur un nombre). C'est l'éclair du panneau d'inspection (« mises à jour »).
- `*offline` se pose sur `<@document>` (toute la page) ou sur une zone : quand le réseau tombe (après `delay`, 1 s), une bande le dit (`text`, `logo`, `place` : `top`, en haut par défaut, ou `bottom`, `size`, `background`, `color`, `opacity`, `zindex`, et `fx` : l'effet qui l'amène) et, avec `count`, compte les changements qui partiront au retour (les messages en attente de `µsocket`, les écritures optimistes en vol) ; la page se grise sous un voile (`veil`, sa force ; `0` : pas de voile — une variable qui règle `veil` est suivie : à `0` le voile part, au-dessus de `0` il revient, derrière la bande). Au retour du réseau, tout s'en va.
- **La connexion.** `*react`, `*follow`, `*cursors` et `*heatmap` passent par le serveur temps réel de MJS (MJS WS), par la connexion que leur donne une variable : `@sock` du composant par défaut — `@sock = µsocket 'wss://exemple.fr/ws'` dans son `<script>`, avec son `auth` —, ou une autre : `sock: $$sock` (un store, rempli une fois — `$$sock = µsocket 'wss://…'` — : une seule connexion pour toute l'appli), `sock: @autre`. Pour `*follow` et `*cursors`, la connexion est le réglage qui s'écrit sans son nom : `*follow($$sock)`, `*cursors($$sock)`. Un composant qui pose un de ces effets sans `sock` et sans `@sock` ne se construit pas (un `@sock` posé par déstructuration, par `Object.assign @, { sock }` ou dans un gestionnaire compte) : le build dit quoi écrire (un bouton `*react(🎉)`, lui, passe par la scène la plus proche, qui tient la connexion). La variable vide (un store rempli à la connexion de l'utilisateur, par exemple) : rien ne part, l'effet le dit en console au bout de deux secondes, et s'y branche dès qu'une connexion y arrive ; avec un `auth`, il attend que l'appli l'ouvre (il ne l'ouvre pas sans l'identité). Il s'en sert sans la retenir : quand l'appli la ferme (`destroy()`, à la déconnexion d'un utilisateur), elle se ferme vraiment. `server: 'wss://…'` lui ouvre à la place sa propre connexion, à cette adresse. Ses trames (positions, émojis) ne partent jamais en file hors ligne, et elles ont leur part du débit de la connexion, pas plus : à eux tous, les effets en direct envoient 4 messages par seconde au plus — positions, points de chaleur ; `"effects": { "rate": 4 }` de mjs.config.json la règle (cf. [32 · CLI et configuration](32-cli-et-configuration.md)). Le serveur en permet 40 par défaut à un visiteur, et expulse qui dépasse : le reste est pour l'appli. Une position retenue n'est pas perdue : la dernière part dès qu'il y a de la place, et la souris d'un autre glisse d'une position à la suivante au même rythme. Le salon, par défaut, est la page et sa route (`#/…`) — `room` en choisit un autre (deux zones du même effet sur une page : un `room` chacune). Sous une View Transition, un effet `*follow`, `*react` ou `*cursors` attend la permutation des vues lancée par le routeur, même si la transition est sautée ; si la permutation échoue, il reste dans le salon de la vue encore affichée. Côté serveur, chaque effet a son paquet (`reactionsPackage`, `followPackage`, `cursorsPackage`, `heatmapPackage` — cf. [23 · MJS-WS](23-mjs-ws.md)) ; un paquet oublié, le serveur ne connaît pas les messages de l'effet : l'effet le dit une fois en console, avec la ligne à ajouter (`app.use(followPackage())`).
- `*react(🎉)` sur un bouton : un clic fait partir l'émoji (le texte du bouton sans lui ; `count` : plusieurs d'un coup ; `rate` : combien par seconde au plus, 5) chez tous les visiteurs de la page. Il vole sur la scène la plus proche : une balise qui porte `*react(stage: true)` (dans sa boîte), sinon la page (`<@document *react>`) ; un bouton sans scène autour en pose une sur la page, avec ses réglages, dès qu'il s'affiche : les émojis des autres montent avant tout clic. La scène tient l'allure : `direction` (où vont les émojis : `up` par défaut, `down` pour une pluie, une diagonale, un angle ; ils partent du bord opposé), `gravity` (la force qui les tire : positive, ils accélèrent comme une chute ; négative, ils freinent comme lancés, -1 par défaut ; 0, vitesse constante), `size`, `duration`, `spread`, `height` (la longueur du trajet), `max`. Sous « réduire les animations », l'émoji ne vole pas : il apparaît puis s'efface sur place. Une zone `*react(stage: true)` posée autour d'un bouton après qu'il a posé la scène de la page reprend ses émojis : la scène de la page part dès qu'aucun bouton ne s'en sert (un émoji reçu ne vole jamais deux fois). Côté serveur : `app.use(reactionsPackage())`, qui a sa propre limite, `rateLimit: { rate: 5, burst: 10 }` par visiteur, et ne relaie que des pictogrammes (un texte, `*react(Bravo)`, demande `reactionsPackage({ emojis: ['Bravo'] })`).
- `*follow(lead: $prof)` : la zone (ou la page, sur `<@document>`) de celui qui mène donne sa position — la balise en haut de son écran et où elle est coupée —, celle des autres y glisse (`ease`, la vitesse ; chaque pas est instantané, même sous `scroll-behavior: smooth` ; une lueur à l'arrivée, `glow`). Un retardataire arrive à la dernière position, tant que le salon n'a pas été vidé : la position ne survit pas à son dernier visiteur. Elle se dit par la balise en haut de l'écran de celui qui mène et un décalage d'une hauteur de balise au plus avant elle : un grand espace devant une petite balise (400 px devant une balise de 100 px) ne se reproduit pas exactement, le public arrive à 150 px de là. Ceux qui suivent voient aussi, de celui qui mène, dans un seul sens (comme `*cursors`) — tout, par défaut : sa souris, avec son nom, et une onde là où il clique (`cursor: pulse` ; `normal` : la souris seule ; `none` : rien) ; ce qu'il sélectionne (`selection` : des bandes sur les mots, son curseur de texte ; dans un champ, le curseur au même rang) ; la balise active (`focus` : le bouton, le lien, le champ où il est), entourée. `selection: false`, `focus: false` les éteignent. Changer ces réglages par une variable ne fait pas disparaître les curseurs des autres, et qui cesse de partager, ou de mener, ne laisse aucun curseur figé chez les autres. Côté serveur : `app.use(followPackage({ canLead: (client) => … }))` pour dire qui peut mener — sans `canLead`, personne ne mène (seul qui peut mener fait voir sa position, sa souris, sa sélection, sa balise active).
- `*heatmap` sur `<@document>` : chaque clic de la page part au serveur — l'adresse de la page (sa route comprise, sans requête ni ancre ; un jeton, un identifiant ou une adresse e-mail y part remplacé par `_SECRET_ID_` — la liste exacte, dans [23 · MJS-WS](23-mjs-ws.md)), la place du clic dans la page et dans chaque composant qu'il traverse (le shadow DOM n'y fait pas obstacle) ; sur une balise, sa zone seule (`name`). `on`, le réglage principal (`*heatmap(mousemove)`) : un nom d'événement, pas une adresse (celle d'un serveur s'écrit `server:`) — un autre événement que le clic (`mousemove`, `dblclick`, `contextmenu`, `keydown`… — sans position de souris, le centre de la balise qui l'a reçu ; dix points par seconde au plus pour tous les `*heatmap` d'une même connexion, qui se les partagent), chacun sa carte. Un point part tout de suite quand la connexion est ouverte et que la part des effets en direct le permet ; sinon il attend, et ceux qui le suivent le rejoignent dans une même trame (20 points au plus attendent : au-delà, les plus anciens s'oublient). La connexion étant paresseuse, le premier point qui attend la fait ouvrir, sauf si l'appli l'a fermée. Quand l'effet est retiré (une navigation), ce qui attend part quand même à l'ouverture, dans les 10 secondes. `show` dessine la chaleur sur la zone elle-même, en direct : `true`, tous les points de la visite ; un nombre, les plus récents (`show: $n`, une variable, le change sur place). Rien d'autre ne part : ni texte, ni identité. Côté serveur : `app.use(heatmapPackage({ origins: ['https://monsite.fr'], maxAge: 30, unit: 'day' }))` — `origins`, obligatoire, dit les origines de vos pages (une trame d'une autre origine est écartée) ; l'âge efface (`maxAge` en `unit` : `second`, `minute`, `hour`, `day`, `week`, `month`, `year` ; 7 jours par défaut), sous trois plafonds de sécurité, réglables (1 million de points, 1 000 pages, 64 zones par page : cf. [23 · MJS-WS](23-mjs-ws.md)) ; `exclude: { ips: ['…'], accounts: ['…'] }` ne compte pas ces IP ni ces comptes (pour ne pas se compter soi-même) ; la carte se lit sur la page d'admin du pont, `/heatmap` (même accès que `/state`), avec un curseur pour n'afficher que les points les plus récents.
- `*autosize` : le contenu change d'abord (un `{if}` qui s'ouvre, une liste qui s'allonge, une image qui arrive) ; avant que l'écran ne se redessine, la boîte repart de son ancienne taille et glisse vers la nouvelle — ce qui dépasse est masqué le temps du glissement. `axis: width` pour la largeur, `both` pour les deux. Sur un champ (`<textarea>`, `<input>`), il ne fait rien — ce qu'on y tape change la valeur du champ, pas son contenu : posez-le sur la boîte qui l'entoure ; en développement, la console le dit.
- `*lang` se pose sur `<@document>` (toute la page) ou sur une balise (les textes qu'elle contient) : au changement de langue (`µlang`), seuls les textes que la bascule change sont animés — `scramble` : brouillés puis recomposés de gauche à droite ; `type` : effacés lettre à lettre, puis tapés. `chars` : les caractères du brouillage ; une apostrophe dans un mot se met entre guillemets doubles (`*lang(chars: "l'été")`).
- `*cursors` montre les autres visiteurs de la même page (`room` : le salon ; la page et sa route par défaut) — `<@document *cursors>`, et côté serveur `app.use(cursorsPackage())`. Ce qu'on voit d'eux se règle comme avec `*follow` — tout, par défaut : leur souris, avec leur nom, et une onde à leurs clics (`cursor: pulse` ; `normal` : la souris seule ; `none` : rien) ; leur sélection (`selection` : des bandes sur les mots, le curseur de texte, leur nom ; dans un champ, le curseur au même rang) ; la balise où ils sont (`focus`), entourée. Chaque visiteur a sa couleur, tirée de son identité ; le nom est celui de son identité sur le serveur (l'`auth` de sa connexion). `max` : les curseurs à l'écran à la fois — ceux qui ont bougé le plus récemment, 20 par défaut ; à partir de 100 visiteurs dans un salon, le serveur regroupe leurs positions (une trame par quart de seconde au lieu d'une par position : cf. [23 · MJS-WS](23-mjs-ws.md)). Un point se dit par le chemin de sa balise et sa place dans la boîte : sur deux écrans de tailles différentes, le curseur tombe au même endroit du contenu. Sur une balise qui défile (ou posée dans une qui rogne), les curseurs sont rognés à la boîte visible de la zone et des parents qui la contiennent vraiment : une zone `position: fixed` n'est rognée par aucun parent, une zone `position: absolute` seulement par son bloc conteneur et ce qui le contient. Le texte lui-même ne part jamais ; un champ mot de passe ne livre rien, pas même sa place de balise active.

## Réussite et échec : `on: success`, `on: error`

Qui sait si une action a réussi ? Le serveur. Deux moments de plus disent quand jouer un effet : à la fin **réussie** (`success`) ou **ratée** (`error`) de l'action de sa balise.

```html
<form action="/inscription" method="post" *shake(on: error)>
  <input name="email" type="email" aria-label="E-mail">
  <button *confetti(on: success)>S'inscrire</button>
  <p class="merci" *fade(on: success)>Merci, à bientôt !</p>
</form>

<button *confetti(on: success) *shake(on: error) @click={µsocket(url).request('vote', { choix: 2 })}>Voter</button>
<button *attention.wiggle(on: error) @click={µ.optimistic($panier, { apply: ajouter, via: envoyer })}>Ajouter</button>
```

L'action d'une balise, c'est :

- **l'envoi du formulaire qui la porte** — le formulaire lui-même, son bouton, un message à l'intérieur. Réussite : le serveur accepte (réponse 2xx). Échec : il refuse (un 422 et ses erreurs de saisie, une page d'erreur) ou ne répond pas (réseau coupé).
- **une promesse rendue par un de ses gestionnaires** (`@click={…}`, `@submit={…}` : l'expression, ou la méthode appelée, rend une promesse). Réussite : elle tient parole, et sa valeur n'a pas `ok: false`. Échec : elle est rejetée — une demande MJS WS à laquelle `.serve()` répond une erreur, un délai dépassé —, ou sa valeur porte `ok: false` — une réponse `fetch` en erreur HTTP, une écriture `µ.optimistic` refusée par le serveur (elle revient alors en arrière d'elle-même).

Chaque effet s'y prête selon sa nature : un effet qui se joue (`*confetti`, `*shake`, `*scramble`, `*count`, `*attention`, `*flash`…) se joue, un effet qui boucle (`*float`, `*pulse`, `*spin`…) fait un tour, une transition posée directement (`*fade`, `*fly`…) reste cachée jusque-là, puis arrive. Un effet à état (`*neon`, `*lift`…) n'a pas de moment : le build le refuse.

- **Quand, exactement.** À la réponse du serveur, avant son affichage : un formulaire que la réponse remplace (une nouvelle page) part avec elle, et son effet avec lui. Les moments servent un formulaire qui reste à l'écran — une réponse `method: none`, un refus en JSON (cf. [21 · Navigation](21-navigation.md)), un envoi par `µsocket`.
- **Rien de caché.** Une promesse rejetée reste une erreur non traitée, visible dans la console comme avant : l'effet la montre, il ne l'avale pas.
- **La valeur, ou l'erreur.** La balise qui porte un de ces effets reçoit aussi l'événement `mjs:success` ou `mjs:error`, la valeur de la promesse (ou l'erreur, ou la réponse du serveur) en `e.data` : `<button *shake(on: error) @click={@voter()} @mjs:error={(e) -> $raison = e.data.message}>`.

## Où poser un effet

Sur **toute balise HTML** et sur **un composant** (`<@card *glitch>`, `<@@select *fade(on: view)>`) : sur un composant, l'effet habille sa balise, et un effet qui dessine un calque (l'onde de `*ripple`, `*skeleton`, `*particles`, `*grid`…) le dessine **dans** le composant. Aussi sur un `<svg>` entier.

Sur **`<@document>`**, les effets de toute la page seulement — la souris (`*ripple`, `*pointer`, `*spotlight` en voile), la langue (`*lang`), le réseau (`*offline`), les autres visiteurs (`*cursors`, `*react`, `*follow`, `*heatmap`) —, avec des valeurs fixes (cf. [Sur toute la page](#sur-toute-la-page--document), plus bas).

Le build refuse un effet :

- sur `<@slot>` et `<template>` — la balise HTML standard dont le contenu n'est jamais affiché, qui sert de moule — : ils n'affichent rien eux-mêmes ; posez l'effet sur une balise qui les entoure ;
- à l'intérieur d'un `<svg>` (sur un `<circle>`, un `<g>`…) — sur le `<svg>` lui-même, oui ; dans un `<foreignObject>`, qui contient du HTML, aussi ; une transition, elle, va sur un tracé SVG (`<path *draw(on: view)>`) ;
- sur une balise du langage autre que `<@document>` : `<@window>`, `<@body>`, `<@html>`, `<@head>`, `<@element>`, `<@module>`, `<@failed>` — et sur `<@document>`, un effet qui n'est pas de toute la page, ou une variable.

Deux familles d'effets demandent une balise qui affiche son contenu :

- les effets qui **dessinent dans leur balise** (`*ripple`, `*skeleton`, `*loader`, `*particles`, `*grid`, `*mesh`, `*noise`, `*shine`, `*underline`, `*unveil`, `*spotlight`, `*pixels`, `*smoke`, `*border`, `*iso`, `*annotate`, `*sparkles`, `*kenburns`, le reflet de `*tilt(glare: true)`) : refusés sur une balise sans contenu affiché — `<img>`, `<input>`, `<textarea>`, `<select>`, `<video>`, `<audio>`, `<canvas>`, `<iframe>`, `<svg>`… ; pose l'effet sur une balise qui l'entoure (`<figure *tilt(glare: true)><img …></figure>`) ;
- les effets qui **travaillent le texte de leur balise** (les effets de lettres, `*count`, `*marquee`, `*split`, `*cycle`, `*circular`, `*wave`) : refusés aussi sur un composant, qui affiche son propre texte — pose l'effet sur une balise de texte, dans le composant s'il le faut.

Sans reflet, `*tilt` se pose sur une image (`<img *tilt>`) ; `*glitch` aussi, qui secoue alors l'image elle-même.

<details>
<summary>🎓 <b>Pour débutants</b> — pourquoi <code>*ripple</code> ne va pas sur un <code>&lt;input&gt;</code>&nbsp;?</summary>

L'onde est dessinée dans un petit calque glissé *à l'intérieur* de la balise. Un `<input>` ou une `<img>` n'affichent jamais ce qu'on met dedans : l'onde existerait, mais personne ne la verrait. Plutôt que de vous laisser chercher pourquoi rien ne bouge, le build le dit tout de suite. La solution tient en une balise : `<label *ripple><input …></label>`.

</details>

> ⚠️ Plusieurs effets qui dessinent avec le même pseudo-élément ne se cumulent pas sur une balise : un seul apparaît. `::after` : `*shine`, `*noise`, `*underline`, `*unveil`, le reflet du tilt, le halo de `*spotlight`, le liseré de `*border(gradient)`, un côté de `*iso`, la lueur du cadre de `*neon(breathe: true)` ; `::before` : le liseré de `*spotlight`, le halo de `*border(gradient)`, l'autre côté de `*iso`, la lueur du texte de `*neon(breathe: true)`, `*kenburns` sur un fond (sans image dans la balise) ; les deux : `*glitch`, `*split`. Une exception : `*border(gradient)` et `*spotlight` se cumulent — posé avec `*spotlight`, le dégradé dessine son liseré et son halo dans un calque de la balise. Le build vous le signale : deux effets d'une même balise qui dessinent dans le même pseudo-élément donnent un avertissement `[lint.collision]` qui les nomme.

## Sur toute la page : `<@document>`

Neuf effets agissent **partout** : posés sur `<@document>`, ils valent pour toute la page, tant que le composant qui les porte est affiché. Trois suivent la souris, un anime les changements de langue, un dit quand le réseau tombe, quatre relient les visiteurs entre eux.

```html
<@document *ripple(#03a9f4, duration: 1s)></@document>
<@document *lang></@document>
<@document *offline></@document>
```

| Sur `<@document>` | Ce qui se passe dans la page |
|---|---|
| `*ripple` | un anneau part de chaque clic (`size` : son diamètre final) |
| `*pointer` | un curseur qui suit la souris dans toute la page : un disque, un anneau, un point ou une lentille |
| `*spotlight(where: veil)` | un voile sombre couvre la page, percé d'un trou de lumière que la souris déplace : on ne lit que dans la lumière |
| `*lang` | au changement de langue, les textes traduits se brouillent puis se recomposent |
| `*offline` | quand le réseau tombe, une bande le dit, la page se grise |
| `*cursors` | les curseurs, les clics et les sélections des autres visiteurs, avec leur nom |
| `*react` | les émojis lancés par les boutons `*react(🎉)` montent chez tous |
| `*follow` | la page du public suit le défilement de celui qui mène |
| `*heatmap` | chaque clic part au serveur, pour la carte de chaleur |

Les quatre derniers passent par une connexion MJS WS que le composant leur donne : sa variable `@sock`, avec l'adresse du serveur — sans elle, le build s'arrête et dit quoi écrire.

```html
<script>
@sock = µsocket 'wss://exemple.fr/ws'
</script>
<@document *cursors *react *heatmap></@document>
```

Leurs réglages se collent au nom (`*ripple(color: red)` ; avec un espace, le build refuse, et sur `<@window>` il dit aussi que l'effet ne s'y pose pas) et sont ceux de la balise (`color`, `duration`, `opacity`, `easing`, `size` pour `*ripple`) :

```html
<@document *ripple(color: #0ff, size: 300) *lang></@document>
```

- **Ces neuf-là seulement.** Les autres effets habillent une balise : un néon, un glitch n'ont pas de sens « partout ». Le build refuse `<@document *neon>` et dit où le poser : sur une balise. `*lang`, `*offline`, `*cursors`, `*react`, `*follow`, `*heatmap`, `*pointer` et `*spotlight` se posent aussi sur une balise, pour ne valoir que pour ce qu'elle contient. `*spotlight` n'y va qu'en voile, `*spotlight(where: veil)` : le halo et le liseré dessinent dans une balise, ils n'ont rien à faire sur la page, et le build refuse tout autre `where`.
- **Des valeurs fixes seulement.** `<@document>` n'est pas une balise du HTML du composant : aucune liaison ne la met à jour, une variable n'y serait jamais suivie. Le build refuse `<@document *ripple($couleur)>` : écris la valeur, ou pose l'effet sur une balise si le réglage doit changer.
- **Quand.** L'effet est posé quand le composant s'affiche, retiré quand il s'en va (route quittée, `{if}` refermé) — comme les écouteurs posés sur `<@document>`.
- **Plusieurs composants.** Si deux composants affichés posent le même effet, le premier posé l'emporte ; il reste tant qu'un des deux est affiché.

## Vos propres effets : le fichier `*.effects.mjs`

Un fichier `*.effects.mjs` du projet (`app/modularjs/effets/mes.effects.mjs`…) contient un bloc `<effects>` : les effets de **votre** appli, valables dans tous ses composants. Deux sortes :

```html
<effects>
  *titre = *scramble(311, on: click, order: left, delay: 420ms)
  *entree = *fly(up, distance: 30px, duration: 250ms)

  *halo(color: #0ff, size: 12px) =
    box-shadow: 0 0 $size $color

  *battement(scale: 1.15) =
    @keyframes
      50%
        transform: scale($scale)
</effects>
```

- **Un effet réglé une fois pour toutes** : `*titre = *scramble(311, on: click)`. Dans un composant, `*titre` pose le `*scramble` avec ces réglages ; `*titre(delay: 0s)` en change un à la pose (les réglages de la pose l'emportent, la valeur sans nom règle le réglage principal de l'effet d'origine). Un effet réglé peut en régler un autre (`*titre-lent = *titre(speed: 80)`). Tout se résout à la compilation : rien n'en reste à l'exécution.
- **Un effet à vous, en CSS** : `*nom(réglage: défaut, …) =` puis ses déclarations, une par ligne, en retrait ; `$réglage` y prend la valeur du réglage. Le premier réglage est le réglage principal : `*halo(#f0f)` = `*halo(color: #f0f)`. Chaque réglage est une variable CSS `--mjs-<nom>-<réglage>` — donc aussi une variable de thème, `$$halo-color`.
  - sans `@keyframes`, les déclarations s'appliquent quand l'effet est actif, selon `on` : `always` (défaut), `hover`, `click`, `view`, `load` — avec une transition de `duration` (400ms) sur les propriétés qu'elles touchent : `<button *halo(on: hover)>` ;
  - avec `@keyframes` (ses étapes — `from`, `to`, `50%` — puis leurs déclarations, plus en retrait), c'est une animation : `on: always` en boucle, `hover`/`view` tant que la condition tient, `click`/`load` un tour ; `duration` (1s), `delay`, `easing` ;
  - sur le cycle de vie (`@in=*halo`, `@out=*halo`, `@transition=*halo`), les déclarations sont **l'état caché** : la balise entre en partant d'elles, sort en y allant ; une animation, elle, se joue une fois (à l'envers pour la sortie).
  - un commentaire `//` s'écrit en fin de ligne, ou sur une ligne à lui, comme dans un bloc `<style>` : il va jusqu'au bout de la ligne et n'arrive pas dans le CSS de l'effet (`box-shadow: 0 0 $size $color // le halo`). Un `//` dans un texte entre guillemets (`content: "//"`), dans `url(…)` (`url(//cdn/fond.png)`) ou dans une adresse à protocole (`https://…`) n'est pas un commentaire ; un `/* … */` est du CSS et reste tel quel. Entre les parenthèses d'un effet (`*halo(color: #0ff) =`, `*titre = *scramble(…)`), un commentaire est refusé, comme sur une balise. Hors des parenthèses, partout dans le bloc — une ligne à lui entre deux effets, ou le bout d'une déclaration (`*titre = *scramble(40) // lent`, `*halo(color: #0ff) = // le halo`) —, il est retiré de même.

```html
<h1 *titre>Bienvenue</h1>
<button *halo(#f0f, on: hover)>Survole</button>
<span *battement(on: hover)>♥</span>
{if $ouvert}<div @in=*entree @out=*halo(size: 40px)>…</div>{end}
```

Le build vérifie tout, fichier par fichier : un nom déjà pris par un effet de la bibliothèque, un nom défini deux fois, un effet réglé qui n'existe pas, des effets qui se règlent en rond, une variable dans le fichier (il vaut pour toute l'appli : passe la variable à la pose, `*titre(delay: $d)`), un `$réglage` non déclaré, un réglage que tout effet a déjà (`on`, `duration`, `delay`, `easing`), un nom que JavaScript donne déjà à tout objet (`constructor`, `toString`, `valueOf`…) pour un effet ou un réglage, un guillemet ou une parenthèse laissés ouverts dans un défaut, une déclaration ou un réglage changé (la feuille de l'effet avalerait la suite, jusqu'à la règle du mouvement réduit), un `$réglage` dans un défaut, un bloc `<effects>` dans un composant. Une faute dans les réglages d'un effet réglé est dite sous le nom que vous avez écrit, avec sa ligne, dans la langue des messages (`app.effects.mjs (ligne 1) : *titre : speed = 9999 — permis : int 10..500.`). Un composant qui pose un effet de l'appli est recompilé quand le fichier change.

### Les alias d'un effet : `*effet.nom`

Un alias est un effet de la bibliothèque réglé une fois pour toutes **et rattaché à son effet** : `*effet.nom = *effet(réglages)`, dans le même fichier `*.effects.mjs`.

```html
<effects>
  *filter.verre = *filter(none, blur: 12, spot: 240, soft: 100)
  *fade.lent = *fade(duration: 3s)
</effects>
```

```html
<img src="photo.jpg" alt="" *filter.verre>
<img src="autre.jpg" alt="" *filter.verre(blur: 20)>
{if $ouvert}<div @in=*fade.lent @out=*fade.lent(duration: 800ms)>…</div>{end}
```

- **L'écriture** : `*effet.nom` pose l'effet avec les réglages de l'alias ; un réglage écrit entre parenthèses à la pose l'emporte (`*filter.verre(blur: 20)`), les autres restent ceux de l'alias. Un alias se pose partout où son effet se pose : sur une balise, après `@in=`, `@out=` et `@transition=`, et sur `<@document>` quand l'effet y va (`<@document *ripple.rouge(size: 90)>`). Un chemin de fichier d'image écrit à la pose (`*behind.fond('photo.jpg')`) est publié comme pour l'effet seul : son adresse part dans le code, le fichier dans la sortie, jamais le chemin tel qu'écrit.
- **Le nom** : des minuscules, des chiffres et `_` (`frosted_glass`, jamais `Verre`, `frosted-glass` ni `1verre`). Un alias se rattache à l'effet qui le précède : `*filter.verre = *tilt(…)` est refusé, comme un alias qui règle un effet CSS de l'appli ou qui porte des déclarations CSS. Un alias qui n'existe pas (`*filter.inconnu`), ou dont le nom sort de cette règle (`*filter.Verre`, mais aussi un point qui ne mène à aucun nom ou qui en suit un autre : `*filter.`, `*filter.net.x`), est une erreur du build — sur une balise, après `@in=`, `@out=` ou `@transition=`, comme sur `<@document>` : elle nomme l'alias tel que vous l'avez écrit, avec sa ligne, rappelle la règle et liste ceux que l'effet connaît. Toute autre faute à la pose d'un alias (un réglage faux ou inconnu, une balise qui ne convient pas, un effet qui ne se joue pas à l'entrée, posé après `@in=`) nomme aussi l'alias en entier, avec sa ligne. Le nom se colle à l'effet et se place avant les réglages : `*filter.net(blur: 3)`. Un point qui suit l'effet sans en faire partie — séparé de lui par un espace (`*filter .net`), collé aux réglages (`*filter.net(blur: 3).x`) ou sans effet devant lui (`*.net`) — arrête aussi le build, sur une balise, après `@in=`, `@out=` ou `@transition=` et sur `<@document>` : l'erreur dit ce que vous avez écrit, avec sa ligne, et la forme attendue.
- **Les alias que MJS livre** : deux cents, pour 55 effets, rangés par effet plus bas (`*filter.frosted_glass`, `*tilt.floating_layers`, `*stagger.title_words`…). Ils s'écrivent sans rien déclarer et ne sont pas copiés dans votre appli. Aucun ne porte d'image ni de cible propre à une page : vous les donnez à l'usage (`*behind.blurred_edge('moi.png')`, `*travel.spin_path('.arrivee')`). Si votre fichier d'effets déclare un alias du même nom, le vôtre remplace celui de MJS, avec un avertissement à la construction.
- **Un alias utilisé au moins six fois** : dès six usages dans l'appli, ses réglages ne sont écrits qu'une fois, dans une table du code de l'appli ; chaque usage y renvoie, avec seulement ce qu'il change. En dessous de six usages, chacun garde ses réglages écrits en clair, comme sans alias : écrite une seule fois, la table ne fait maigrir le fichier brut qu'à partir d'environ six usages ; compressée, elle fait gagner des octets quand les usages sont répartis sur plusieurs composants, et en coûte quelques dizaines quand ils tiennent dans un seul fichier. Un alias dont chaque usage tient un de ses réglages par une variable (`*filter.verre(blur: $b)`) reste écrit en clair, quel que soit le nombre d'usages, et rien n'est ajouté à une appli qui n'a pas d'alias. Le code que les réglages d'un alias demandent à l'effet (ses sections) arrive de la même façon, que l'alias soit en table ou écrit en clair.

#### Les alias que MJS livre, par effet

Chaque alias pose l'effet avec les réglages qui donnent l'aperçu décrit ; `*effet.nom(réglage: valeur)` en change un à la pose. Les images (`image` de `*behind` et de `*sprite`, `images` de `*scrub`) et les cibles propres à une page (`to` de `*travel`, `of` de `*fly`) ne sont dans aucun alias : vous les écrivez à l'usage, `*sprite.four_directions('marche.png')`, `*scrub.on_hover(images: ['a.jpg', 'b.jpg'])`. Ceux des transitions (`*fly`, `*iris`, `*blocks`, `*scale`, `*pixelate`) portent leur déclencheur (`on`) : ils se posent sur une balise, pas après `@in=`. Les alias de transition qui n'en portent pas (`*ink.brush`, `*iris.box`, `*wheel.four_spokes`, `*fly.light_speed`, `*scale.stretch_x`, `*rotate.quarter_turn`) se posent après `@in=`, `@out=` ou `@transition=`, comme leur effet.

## Les régler pour toute l'appli : les variables de thème

Chaque réglage **visuel** d'un effet est une variable de thème `$$<effet>-<réglage>`. Posée dans un bloc `<theme>` ou un `<style>`, elle règle tous les effets de ce nom dans la descendance ; un réglage écrit sur la balise l'emporte.

```html
<theme>
  $$neon-color: #f0f
  $$neon-size:  1.5
</theme>
```

La cadence des effets qui se répètent a, elle, sa variable commune.

### Une cadence commune : `$$mjs-fx-every`

Les effets qui se répètent ont un réglage `every`, le temps entre deux passages : `*shine`, `*attention`, `*glitch` et `*annotate`. La variable de thème `$$mjs-fx-every` leur donne une cadence commune : posée dans un bloc `<theme>` ou un `<style>`, elle vaut pour toute la descendance, et `every` écrit sur la balise l'emporte. L'éclat de `*spotlight` a son propre réglage (`every` sur la balise, ou `$$spotlight-every`), que la cadence commune ne touche pas.

```html
<theme>
  $$mjs-fx-every: 4s
</theme>

<button *shine(on: always)>Un reflet toutes les 4 s</button>
<button *shine(on: always, every: 2s)>Un reflet toutes les 2 s : la balise l'emporte</button>
```

L'ordre : `every` écrit sur la balise ; puis `$$mjs-fx-every` ; puis le défaut de l'effet (3 s pour `*shine`, `*attention` et `*annotate`, 5 s pour `*glitch`) — sans variable, chaque effet garde son défaut. Pour `*attention` et `*annotate`, `every` reste la pause entre deux passages. La variable règle une cadence, elle ne fait rien répéter : un `*shine` au survol ou un `*attention` à l'arrivée à l'écran, sans `every` écrit, passent une fois. La cadence commune ne met en marche aucun effet : l'éclat de `*spotlight` ne s'allume que par `every` écrit sur la balise ou par `$$spotlight-every`, et bat alors à leur durée.

La valeur de `$$mjs-fx-every` suit la règle de `every` écrit sur la balise : une durée (`300ms`, `1.5s`, `0`). Une valeur refusée (`-1s`, `2` sans unité, `abc`) est ignorée : chaque effet garde son défaut, et la console du développement le dit une fois par valeur. `0` vaut `every: 0` écrit sur la balise. La cadence est relue à chaque passage, au moment de programmer le suivant : un thème qui change en cours de route vaut à partir de là (le passage déjà programmé garde son heure).

Les effets qui ont le même rythme battent ensemble. Le premier passage de `*shine`, `*attention` et `*annotate` part tout de suite (à la pose avec `on: always`, à l'arrivée à l'écran avec `on: view`) ; les suivants se calent sur une horloge commune, aux multiples du tour comptés depuis le début de la page, le prochain un tour entier au moins après le premier, et deux reflets posés à des moments différents passent ensuite au même instant. La première salve de `*glitch` part, comme avant, 2 s après la pose ou l'arrivée à l'écran (après un tour, s'il est plus court) ; les suivantes se calent de même, la prochaine un tour entier au moins après elle. Le tour, c'est `every` pour `*shine`, `*glitch` et l'éclat de `*spotlight` ; l'appel et sa pause pour `*attention` (`duration` × `repeat` + `every`) ; le tracé et sa pause pour `*annotate` (`delay` + `duration` + `every`). Le calage vaut pour `on: always` et `on: view` ; au survol (`on: hover`), le premier passage part à l'entrée de la souris.

> ⚠️ Les effets lisent toujours des variables en `--mjs-…`, comme les modules cœur : une appli qui change `varPrefix` (cf. [31 · Thèmes](31-themes.md)) règle ses effets en écrivant `--mjs-neon-color` tel quel, et non `$$neon-color` (de même `--mjs-mjs-fx-every`).

## Les anciens noms (avant la 3.0)

Sept effets ont rejoint un effet voisin, et des préréglages et des styles trop proches d'un autre ont été retirés. Un ancien nom arrête la construction, et le message dit quoi écrire à la place — sur une balise, sur `<@document>`, après `@in=` comme dans un fichier `*.effects.mjs`.

| Ancien effet | S'écrit maintenant | Ses réglages |
|---|---|---|
| `*shimmer` | `*shine.shimmer` | `speed` → `duration` et `every`, de même valeur (le reflet repart à la fin de chaque passage) ; `color` (le texte) → `ink` ; `shine` (le reflet) → `color` |
| `*wiggle` | `*attention.wiggle` | `duration: d` → `duration: d, every: 3 × d` (le repos de l'ancien balancement) ; `angle` s'écrit avec son nom |
| `*aurora` | `*mesh.aurora` | les couleurs s'écrivent avec leur nom : `colors: […]` |
| `*lens` | `*filter.lens` | le rayon `size` devient le diamètre `spot`, le double |
| `*knockout` | `*gradient.knockout` | une image tenue par une variable s'écrit avec son nom : `image: $photo` |
| `*texture` | `*gradient.texture` | `style` → `pattern` (tenu par une variable : `pattern: $motif`) |
| `*typing` | `*cycle.frame` ; `*typing.typewriter` et `style: type` : `*cycle.typewriter` | les autres réglages gardent leur nom |

Le message traduit les réglages que vous avez écrits : `*shimmer(speed: 1s)` donne `*shine.shimmer(duration: 1s, every: 1s)`. Il ne promet le même rendu que pour l'ancien nom écrit sans réglage ; un réglage qu'il ne sait pas traduire (la durée de `*wiggle` tenue par une variable, un réglage que l'ancien effet n'avait pas) est nommé, à reporter d'après la correspondance ou à retirer. Une valeur hors de la plage du nouvel effet (`*lens(blur: 55)`, quand `*filter` s'arrête à 50) est ramenée à sa borne dans l'écriture proposée, et le message le dit. Dans un fichier d'effets, où un alias ne s'écrit pas en cible, il donne l'écriture complète (`*titre = *lens(150)` → `*titre = *filter(style: none, blur: 10, spot: 300, …)`), et un alias de l'ancien effet se rattache au nouveau (`*shimmer.lent = *shimmer(speed: 4s)` → `*shine.lent = *shine(…, duration: 4s, …, every: 4s)`).

**Les préréglages et les styles retirés** donnent l'écriture qui les remplace : `*focus.blur_others` → `*focus` (le même réglage) ; `*physics.soft_fall` → `*physics` ; `*loader.arc` et `*loader(arc)` → `style: neon` (le même dessin) ; `*loader.swirl` et `*loader(swirl)` → `style: galaxy` ; `*peel.bottom_left` → `*peel(corner: bottom-left)` ; les autres (`*pointer.disc`, `*tilt.slow_follow`, `*gallery.coverflow`…) → leurs réglages, écrits sur l'effet. La palette `aurora` de `*mesh` s'appelle maintenant `boreal` : `*mesh(aurora)` est refusé et le dit — `*mesh.aurora`, lui, est l'ancien effet `*aurora`, pas cette palette.

**Le style `flash` de `*attention`** s'appelle maintenant `blink` : il se confondait avec l'effet `*flash`. `*attention(flash)`, `*attention(style: flash)` et `*attention.flash` arrêtent la construction et proposent `blink` (`*attention(blink)`, `*attention(style: blink)`).

**Les variables de thème** des anciens effets ne sont plus lues. Posées dans un `<theme>`, un `<style>` ou un fichier de thème, elles donnent un avertissement de construction (`lint.legacy`) qui nomme leur remplaçante : `$$shimmer-color` → `$$shine-ink`, `$$shimmer-shine` → `$$shine-color`, `$$shimmer-speed` → `$$shine-duration`, `$$wiggle-…` → `$$attention-…`, `$$aurora-…` → `$$mesh-…`, `$$knockout-…` et `$$texture-…` → `$$gradient-…`, `$$typing-…` → `$$cycle-…`. `$$lens-size`, `$$lens-blur` et `$$lens-color` n'ont pas de remplaçante : écrivez le réglage sur la balise. Une appli qui a son propre effet de ce nom (`*aurora(…) =` dans son fichier d'effets) n'est pas avertie : ses réglages sont ses variables.

Dans `mjs.config.json`, `runtime: ['fx_aurora']` (le module d'un effet fondu) est refusé comme un module inconnu, et le message nomme celui qui porte maintenant l'effet (`fx_mesh`).

## Ce que MJS fait de lui-même

Quatre effets n'ont rien à écrire : MJS les pose seul, et la clé `effects` de `mjs.config.json` les règle (cf. [32 · CLI & configuration](32-cli-et-configuration.md)).

- **Le thème en cercle.** Quand un clic change le thème (`<button @click={µtheme = 'dark'}>🌙</button>`), le nouveau thème s'ouvre en cercle depuis le point cliqué, en une demi-seconde, par une transition de vue du navigateur ; au clavier (Entrée, Espace), depuis l'élément actif. Une bascule qui ne suit pas un geste (le système passe en sombre, votre code change `µtheme`) se fait d'un coup, comme avant ; de même sans transitions de vue (navigateur ancien) ou avec « réduire les animations ». `"effects": { "theme": "none" }` : toujours d'un coup. Les transitions de page (`@viewTransition`) ne changent pas.
- **Les effets économes.** Sur un appareil qui peine (vieux téléphone, économie d'énergie), les effets lourds se calment d'eux-mêmes : les particules, étincelles, fumées, gouttes et confettis passent au tiers de leur nombre, les taches de `*mesh` et le grain s'arrêtent (ils restent à l'écran). MJS mesure la fluidité de la page tant qu'un de ces effets est posé : pendant environ 150 images à la pose du premier (un appareil lent qui joue seul est ainsi jugé sans que personne ne touche à la page ; une image de 250 ms ou plus, un point d'arrêt par exemple, ne compte pas, et une page qui n'a que de telles images n'est pas jugée : passé 150 de ces images, seul un geste relance la mesure), puis seulement pendant que la page travaille (un geste du pointeur, de la molette, un défilement, et dans Chromium une image que le navigateur juge longue : Firefox et Safari ne la signalent pas) et jamais au repos : deux mesures de suite sous ~36 images par seconde, et la page devient économe pour le reste de la visite ; un appareil en économie de données l'est d'emblée. `"effects": { "lite": "on" }` : toujours économe ; `"off"` : jamais. Votre feuille peut suivre : `<html>` porte alors l'attribut `mjs-fx-lite`.

- **Le squelette des chargements.** Ce qui n'est pas encore arrivé garde sa place, en gris qui scintille : un `{await}` sans branche d'attente montre la silhouette de sa branche `{success}` (comme `{await … *skeleton}`) ; un module dont les textes traduits sont en route attend, caché, et paraît d'un coup (`wait`, le défaut de l'attente des textes, [29](29-i18n.md)) ; avec `@i18nPlaceholder *skeleton`, chaque texte en route est une barre grise à sa place (en développement, sa clé) — ces barres se règlent par `i18n.placeholder` et `i18n.timeout`, pas ici. `"effects": { "skeleton": [...] }` choisit : `await` (le défaut) et `components` — un composant qui attend un contenu (un `{await}` dans son HTML) montre la silhouette de son HTML le temps que son code arrive ; un composant sans attente (mise en page, cadre, en-tête, tiroir, barre fixe) n'en a pas : il est rendu dès que son code arrive, et une silhouette dessinée sans son style (qui arrive avec ce code) n'aurait pas sa place — un tiroir hors de l'écran ou une barre fixe s'y dessineraient dans le flux, puis la page sauterait. Ce qui le suit dans la page se voit tout de suite ; à son arrivée, un composant de structure dans le flux le pousse de la place qu'il prend (un composant fixe ou absolu ne pousse rien). Comme sur une balise, la silhouette paraît une fois en place les composants encore en route placés avant elle. Le build range ces silhouettes dans le manifeste en forme compacte : quelques centaines d'octets par composant qui en a une, rien pour les autres (une silhouette rangée en HTML entier, par un build plus ancien, se lit aussi) ; `[]` : rien. Sans `components`, `*skeleton` sur la balise d'un composant le fait pour lui seul.

- **Le champ qui se garde.** Un champ (`<input>`, `<textarea>`, `<select>`) lié à une variable typée (`<input value=!{$age}>`, `$age int 18..120` dans le `<vars>`) reçoit `*guard` comme s'il était écrit : une frappe hors de la règle ne part pas dans la variable (taper « 120 » passe par « 1 », qui n'est plus réécrit « 18 » sous les doigts) ; une pause d'une seconde sur une valeur hors de la règle, et le champ fait « non » de la tête, une bulle dit ce qui est permis ; à la sortie du champ la valeur est ramenée dans sa plage. Un store typé aussi, même quand sa règle est posée par un autre composant. Un `*guard` écrit garde ses réglages. `"effects": { "guard": { "delay": "1.5s" } }` : la pause de tous les champs gardés (un nombre de millisecondes, ou `"800ms"`, `"1.5s"`, au plus 24 h, soit 86 400 000 ms). `"effects": { "guard": false }` : ces champs-là sans spectacle — ni secousse ni bulle, la frappe toujours à l'abri, la valeur ramenée à la sortie (cf. [37 · Types](37-types.md)).

```json
{ "effects": { "theme": "none", "lite": "off", "skeleton": ["await", "components"], "guard": { "delay": "1.5s" } } }
```

## Mouvement réduit, rendu serveur

- **« Réduire les animations »** (réglage du système) : plus rien ne bouge. Les boucles s'arrêtent, les apparitions montrent la balise à sa place, `*scramble` et `*count` affichent tout de suite le texte final (les volets de `*count(style: flip)` changent de chiffre sans basculer), `*cycle` montre ses mots sans les animer (ni relais, ni cadre, ni frappe), `*dissolve` efface le texte sans poussière, les confettis, les ondes et les étincelles ne partent plus, la neige et les étoiles filantes restent immobiles, réparties dans la balise (jamais empilées dans un coin), le réseau se dessine une fois, sans boucle, un `*loader` se fige (il reste visible : il dit toujours que ça charge).
- **Rendu serveur** : la page prérendue montre la balise sans son effet ; l'effet se pose quand le composant prend vie dans le navigateur.
- **Sans `IntersectionObserver`** (navigateur ancien) : un effet réglé `on: view` se joue tout de suite.

## Dans le fichier de l'appli

Le build n'embarque que les effets écrits dans le HTML des composants (et sur `<@document>`) : le moteur des effets, plus le code de chaque effet utilisé. Un projet sans effet n'en emporte rien (cf. [22 · Aide-mémoire](22-aide-memoire.md), « Runtime à la carte »). Une transition embarque son animation ; un effet réglé du fichier `*.effects.mjs` ne pèse que l'effet qu'il règle ; un effet CSS de l'appli part avec les composants qui le posent.

**Le code d'un effet arrive avec le composant qui l'écrit.** Le moteur est au cœur ; le code de chaque effet a son propre fichier (`mjs_fx_neon-<empreinte>.js`), importé par les composants qui le posent. Une page ne charge donc que ses effets : une page qui en montre six n'emporte pas le code des autres effets de l'appli. Ils partent **en même temps** que les composants qui les écrivent — préchargés avec ceux de la page (et dans l'en-tête d'une page prérendue), chargés avec un composant qui arrive plus tard, jamais après lui. Un effet nommé pendant l'exécution (`*delta(fx: $effet)`, l'effet choisi par une variable) arrive à la demande, en arrière-plan, et se joue dès qu'il est là : tout effet qui se joue une fois, et une transition si elle est écrite ailleurs dans l'appli (son animation est alors déjà là). En fichier unique (`js: 'bundle'`), rien à découper : tout reste dans le fichier, et une variable n'y nomme qu'un effet écrit ailleurs dans l'appli ; `runtime: ['fx_neon']` garde un effet au cœur. Restent au cœur le squelette (le cœur s'en sert pour ses chargements), les transitions et les effets CSS de l'appli.
